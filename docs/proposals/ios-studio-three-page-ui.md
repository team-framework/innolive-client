# iOS 방송 화면 3페이지 구성 제안

- 작성: 2026-10-19
- 탐구 기준: origin/main `1dd529ca`
- 대상: apps/ios, 홈 방송 UI와 화면용 미리보기 배치
- 계약 영향: 없음. API·signaling·캡처 프레임·방송 수명주기를 유지한다.
- 상태: 코드·기존 동작 문서·사용자 첨부 14장 기반의 초기 제안. 후속 구현과 검증 범위는 [iOS 방송 화면 탐색](../ios-studio-navigation.md)에 기록한다.

## 방향

전체 화면 영상을 고정하고, 그 위의 조작 영역을 좌우 스와이프로 전환한다.
진입 위치는 가운데 ‘기본’이다. 왼쪽은 ‘화면’, 오른쪽은 ‘방송 설정’이다.
‘화면’으로 가려면 오른쪽으로, ‘방송 설정’으로 가려면 왼쪽으로 민다.

```text
         화면             기본 · 최초 진입           방송 설정
      영상에 집중     ↔   자주 쓰는 조작       ↔     상태와 세부 설정
───────────────────────────────────────────────────────────
             같은 영상 레이어와 방송 세션을 유지
```

참고 화면에서 가져올 요소:

- IMG_0015: 전체 영상 위 상단 도구, 하단 방송 요약 카드와 주요 버튼.
- IMG_0016: 하단 조작을 감추고 영상을 넓게 보는 구성.
- IMG_0017: 영상 배경을 유지한 별도 역할의 페이지와 위치 표시.
- IMG_0018: 관련 설정을 묶는 패널. 첫 버전에서는 이 패널을 상세 페이지로 정리한다.
- IMG_0023~0024: 방송 중 상단 상태·종료, 하단 소수 도구와 채팅.
- IMG_0025~0028: 선택한 도구의 설정만 하단 시트로 표시.
- IMG_0019~0021: 계정·방송 이력·앱 설정은 별도 화면으로 유지.

사진의 PRISM 기능 목록을 그대로 추가하지 않는다. 현재 InnoLive의 방송·비식별화·원본 비교 기능에 이 구성을 적용한다.

## 페이지별 배치

| 영역 | 화면 | 기본 | 방송 설정 |
| --- | --- | --- | --- |
| 배경 | 전체 영상 | 동일한 전체 영상 | 동일한 전체 영상, 설정 영역에만 어두운 반투명 배경 |
| 상단 | 페이지 표시, 방송 중 작은 LIVE·경과 시간·종료 | 페이지 표시, 카메라 전환·더보기, 방송 중 LIVE·경과 시간·종료 | 페이지 표시, 방송 중 LIVE·경과 시간·종료 |
| 가운데 | 조작 없이 영상 확인 | 영상 확인, 필요한 경우 원본 비교 PiP | 세로 스크롤 설정 패널 |
| 하단 | 기본 페이지 복귀 진입점 | 준비 전 방송 요약 카드·주요 버튼, 방송 중 소수 도구·채팅 | 설정 항목과 대상별 동작 |
| 정상 상태 지표 | 감춤 | 연결 정상/주의 등 한 줄 요약 | 플랫폼별 상태, 실제 화질·FPS·전송량 등 현재 제공 지표 |
| 오류 | 즉시 조치가 필요한 오류 한 줄과 진입점 | 같은 오류 | 오류 원인과 재시도 |

‘화면’ 페이지에서 채팅·원본 PiP·일반 통계·설정 버튼을 감춘다. 방송 중임을 구분하고 종료할 수 있는 작은 상단 영역은 남긴다. 나머지 UI를 완전히 감추는 기능은 첫 버전 범위에서 제외한다.

### 기본 페이지

준비 전:

- 하단 카드 한 장에 선택 플랫폼·채널, 방송 제목, 화질과 처리 방식 요약을 표시한다.
- 카드 탭으로 방송 정보 시트를 연다. 미연결·필수값 누락은 해당 항목과 연결한다.
- 주요 버튼은 ‘방송 준비’. 기존 동의·권한·저장 검증을 통과한 뒤 준비를 실행한다.
- 계정·요금제·저장된 방송은 더보기에서 접근한다.

준비 완료:

- 주요 버튼은 ‘방송 시작’, 별도 ‘준비 취소’를 제공한다.
- 준비만으로 실제 방송을 시작하지 않는다. 기존 카운트다운을 유지한다.

방송 중:

- 상단에 경과 시간과 종료를 고정한다. 종료에는 기존 확인 절차를 적용한다.
- 하단 도구는 비식별화, 영상 조절, 얼굴 등록, 채팅 표시 정도로 제한한다.
- 비식별화 상태는 아이콘과 짧은 값으로 읽을 수 있게 표시한다. 얼굴 비식별화·화면 블러 선택은 기존 동작을 재사용한다.
- 채팅은 하단 제한 높이에 표시하며 숨기기를 제공한다. 원본 PiP와 겹치지 않게 예약 영역을 계산한다.
- 전체 일시정지·재개는 방송 제어 시트로, 대상별 제어는 상세 페이지로 연결한다.

마이크 음소거·카메라 끄기·공유·시청자 수는 사진만 보고 신규 버튼을 추가하지 않는다. 연결된 동작과 실제 데이터 지원을 별도로 확인해야 한다.

### 방송 설정 페이지

1. **송출 대상**: YouTube·치지직 상태, 대상별 방송 정보 수정, 일시정지·재개·종료. 현재 상태에서 허용하는 동작만 활성화한다.
2. **영상·오디오**: 해상도·프레임 설정, 카메라·입력 장치, 영상 조절로 진입한다. 방송 중 화질 변경은 기존 방송 방식 변경 흐름을 사용한다.
3. **비식별화**: 처리 방식, 얼굴·화면 블러 상세 설정, 얼굴 등록 진입을 제공한다.
4. **모니터링·저장**: 원본 비교 표시, 채팅 표시, 현재 방송 상태 상세와 녹화 상태를 묶는다.
5. **이용 정보**: 사용량과 요금제, 해당하는 업그레이드 제안을 표시한다.

설정 페이지는 요약 행과 진입점으로 구성한다. 긴 입력 폼은 하단 시트에서 편집하고, 닫으면 같은 페이지와 스크롤 위치로 돌아온다. 계정 관리·약관·일반 설정은 기존 별도 화면에 둔다.

## 영상과 제스처 규칙

- 준비 전에는 로컬 카메라를 메인 배경에 표시한다. 준비 후에는 기존 처리 영상으로 전환한다. 로컬 원본과 처리 결과를 혼동하지 않게 전환 상태를 표시한다.
- 처리 영상 대기·실패 때 원본을 처리 결과처럼 대체 표시하지 않는다. 기존 준비·복구 표시를 유지한다.
- 영상 뷰를 페이지마다 생성하지 않는다. 페이지 전환은 세션 생성·종료, WebRTC 연결, 캡처 시작·정지, 녹화를 호출하지 않는다.
- 페이지가 바뀌어도 영상의 크롭·방향·미러링·줌·표시 영역을 바꾸지 않는다. 전체 화면 채움과 실제 송출 프레임의 비율 차이는 구현 전 샘플 화면으로 확인한다.
- 기본 페이지의 원본 비교 PiP는 기존 위치를 기억한다. 화면 페이지에서는 숨기고 돌아오면 복원한다. 상세 패널이 열려 있을 때도 가린다.
- 좌우 이동은 페이지, 상하 이동은 기존 CameraInputSwipe 카메라 전환, 두 손가락은 줌으로 분리한다.
- PiP에서 시작한 드래그는 PiP 이동에만 사용한다. 슬라이더·설정 스크롤·채팅·시트에서 시작한 조작을 페이지 이동으로 처리하지 않는다.
- 얼굴 선택 중에는 페이지 이동을 잠그고 얼굴 선택·취소를 우선한다. 준비·시작·종료 오버레이도 같은 우선순위를 갖는다.
- 페이지 점 외에 탭 가능한 페이지명과 VoiceOver 이전/다음 동작을 제공한다. 기본 페이지 진입 시 짧은 좌우 안내를 한 번 표시한다.
- 동작 줄이기에서는 이동 대신 짧은 페이드 또는 즉시 전환을 사용한다. 투명도 줄이기에서는 패널 배경을 불투명하게 한다.
- 가로 화면에서도 같은 3페이지 순서를 유지한다. 기본 도구는 짧은 측면 영역에 배치하고 상세 패널은 스크롤한다.

## 구현 구조 제안

```text
HomeView (카메라·방송 객체와 기존 생명주기 유지)
 ├─ StudioVideoStage (로컬/처리 영상, 원본 PiP)
 ├─ StudioChromePager (화면 / 기본 / 방송 설정)
 ├─ StudioStatusHeader (방송 상태·종료)
 ├─ StudioSheetHost (방송 정보·영상 조절·상태 상세)
 └─ 기존 준비 / 시작 / 종료 / 오류 / 얼굴 선택 오버레이
```

명칭은 제안이다. `StudioPage` 같은 화면 전용 enum과 표시 설정을 도입하되 `YouTubeIntegration`의 방송 상태와 분리한다.

우선 후보는 고정 영상 위 투명한 paging 컨테이너다. 네이티브 paging을 먼저 실험하고, 빈 영역 hit testing·상하 스와이프·PiP 드래그가 충돌하는지 확인한 후 구현을 확정한다. 단순히 DragGesture.onEnded에서 화면을 교체하는 구현은 손가락 추적·전환 중 취소를 충분히 표현하지 못한다.

현재 BroadcastControllsView 내부에 있는 시트·confirmationDialog 상태는 안정적인 상위 호스트로 이동해야 한다. 페이지가 화면에서 빠졌다고 편집 초안·진행 중 동작이 사라지지 않도록 한다. 페이지 onAppear에서 준비나 설정 저장을 실행하지 않는다.

튜토리얼의 primaryButton·liveStatus anchor는 새 위치에 연결한다. 숨겨진 페이지를 대상으로 안내하지 않는다. 필요한 페이지를 선택한 뒤 안내한다.

## 구현 순서와 완료 기준

1. 영상 레이어·컨트롤 책임을 분리하고 3페이지 전환을 연결한다. 기존 처리 영상과 세션 유지부터 검증한다.
2. 준비 전 로컬 전체 미리보기와 기본 요약 카드, 공통 상태·종료 영역을 구성한다.
3. 상세 페이지로 기존 동작을 옮기고 시트·튜토리얼·오류 우선순위를 정리한다.
4. 실제 화면에서 세로·가로·큰 글씨·제스처·원본 PiP·얼굴 등록을 확인한다.

검증할 항목:

- 기본 페이지 최초 진입, 좌우 3페이지 순서, 끝 페이지 경계, 탭·VoiceOver 대체 이동.
- 반복 스와이프 전후 세션 ID·PeerConnection·방송 시작 시각·녹화 연속성 유지.
- 상하 카메라 전환, 핀치 줌, PiP 드래그, 상세 스크롤·슬라이더가 페이지 이동과 충돌하지 않음.
- 준비 전 로컬 영상, 준비 중 상태, 처리 영상 연결·복구, 원본 비교, 전후면 미러링 유지.
- 설정 저장 실패 시 준비 미호출·초안 유지. 준비 성공 후 별도 시작 동작 유지.
- 다중 송출 일부 실패·재시도·일시정지·전체 종료, 라이브 정보 수정·방식 변경 잠금 유지.
- 모든 페이지에서 방송 종료와 중요한 실패에 접근 가능. 정상 지표를 숨겨도 오류를 놓치지 않음.
- iPhone 세로·가로, Dynamic Type, Reduce Motion, VoiceOver 렌더링 및 수동 조작 확인.

회귀 테스트 후보: CameraInputSwipeTests, CameraZoomTests, LocalPreviewSnapLayoutTests,
BroadcastPreparationFlowTests, BroadcastLifecycleTests, BroadcastLiveStatusTests,
BroadcastModeTests, LiveBroadcastEditingTests, BroadcastTutorialTests,
BroadcastRecordingCoordinatorTests. 변경한 경계에 맞춰 선택 실행하고,
시뮬레이터 빌드·화면 검증과 실기기 송출·외부 수신 검증을 구분한다.

최초 탐구 단계에서는 제품 코드를 수정하지 않았다. 이후 사용자의 병렬 구현 요청에 따라 구현을 진행했으며, 실제 반영 범위는 별도 동작 문서에서 확인한다.
