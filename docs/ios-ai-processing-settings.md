# iOS AI 설정과 온디바이스 송출

관련 이슈: client #285, server #264. 기존 로컬 인식 구현과 측정은
[iOS 얼굴 등록 기록](ios-local-face-registration.md)을 참고한다.

## 동작

- 설정 → AI & Faces Setting에서 서버 AI / 온디바이스 AI를 선택한다. 기본값은 서버다.
- 방송 중에는 변경할 수 없다. `server` 세션은 기존 세션·WebRTC·카메라를 유지하고 AI 처리 위치만
  전환한다. 온디바이스 세션은 방송 준비를 취소한 뒤 다시 선택한다.
- 얼굴 관리는 선택한 저장소의 목록만 표시한다. 원래 자동 촬영 화면과 500px JPEG,
  연속 3회 안정된 얼굴 검사 흐름을 재사용한다. 이름은 성공 응답 뒤 비운다.
- 서버 등록은 기존 API에 `images` 한 장과 `name`을 전송한다. 로컬 등록은 같은
  촬영 이미지를 YuNet 정렬과 AdaFace 원본·좌우반전 임베딩에 사용하고 이미지 자체를 저장하지 않는다.
- 기존 Local 앱의 등록 데이터는 그 앱의 컨테이너에 남는다. 일반 앱으로 자동 복사하지 않는다.

## 송출 경로

카메라 → iPhone의 YOLO 분할·YuNet·AdaFace → 비식별화 합성 → H.264 인코더
→ RTMP(S) → YouTube·치지직. 서버 #438 이후 온디바이스 세션은 서버를 거치지 않고
앱이 플랫폼으로 직접 송출한다(client #481). 서버는 방송 생성·라이브 전환·종료만 맡는다.
세션 응답의 `ai_processing`이 `on_device`가 아닌 구 서버에서는 기존 WebRTC 중계 송출을 쓴다.

직접 송출 구현:

- RTMP(S) 송출은 HaishinKit 2.2.5(`RTMPHaishinKit`, BSD-3-Clause)를 쓴다. H.264 High,
  키프레임 2초, B-frame 없음, 1080p 6Mbps·720p 3.5Mbps, AAC 48kHz 스테레오 128kbps다.
- publish 전에 같은 형식의 검은 화면과 무음을 넣어 둔다. HaishinKit은 publish 시점 입력으로
  `onMetaData`를 만들기 때문에, 입력이 없으면 영상·음성 정보가 빠진다.
- 영상은 WebRTC 송출 트랙과 같은 가림 처리·색 보정 결과를 쓴다. WebRTC 프레임의 회전
  정보를 `VTPixelRotationSession`으로 픽셀에 적용한다. 원본 미리보기 프레임은 넘기지 않는다.
- 음성은 앱이 `AVAudioEngine`으로 마이크를 녹음해 48kHz 스테레오로 바꿔 보낸다. 직접 송출
  세션에서는 WebRTC 오디오 송신기에 트랙을 붙이지 않아 WebRTC가 마이크를 열지 않는다. 오디오
  m-line은 남겨 서버와의 SDP 형태는 그대로다. 서버는 이 세션의 음성을 쓰지 않는다.
- WebRTC 음성 처리 모듈(`LKRTCDefaultAudioProcessingModule`)의 capture post-processing으로
  음성을 복사하는 방식은 버렸다. iPhone 15에서 콜백이 한 번도 호출되지 않았다(2026-10-12).
- YouTube는 음성 트랙이 없으면 스트림을 활성으로 보지 않아 라이브 전환을 `broadcast_not_ready`로
  거절한다(2026-10-12 실기기). 마이크 음성이 0.3초 넘게 없으면 그 구간을 무음으로 채운다.
  마이크를 열지 못하면 무음으로 송출하고 방송 화면에 경고를 띄운다.
- 일시 중지·백그라운드 화면은 서버 모드와 같은 안내 화면이다. 서버 에셋
  (`internal/media/assets/cancel-*.png`)을 `Resources/DirectPublishPause*.png`로 복사해 쓴다.
  서버에서 문구·디자인을 바꾸면 이 파일도 함께 바꾼다.
- HaishinKit 로그는 trace 단계에서만 RTMP 명령을 출력한다. 앱은 기본 info 단계를 바꾸지 않는다.
  `RTMPStreamInfo.resourceName`에는 스트림 키가 들어 있으므로 출력하지 않는다.
- 라이브 중에는 15초마다 서버에 하트비트를 보낸다. 서버가 한도·입력 없음으로 끝낸 대상은
  응답의 `stop_targets`로 받아 즉시 연결을 끊는다.
- API 계약은 [온디바이스 직접 송출 계약](../contracts/api/direct-publish-v1.md)을 따른다.
  세션 생성 본문, 해상도, WebRTC 유지처럼 iOS가 고른 방식과 계약과 다른 점은
  [AI 처리 계약](../contracts/api/ai-processing-v1.md)의 iOS 절에 적는다.

직접 송출 미검증 범위(2026-10-12):

- 치지직 실채널 송출·종료. YouTube 라이브 전환과 일시 중지 안내 화면은 iPhone 15에서 확인했다
- 백그라운드 체류 뒤 재연결과 치지직 방송 유지 여부
- 동시 송출 시 인코더 2개의 발열·배터리
- 블루투스 마이크 연결·해제, 통화 중단 뒤 마이크 복구
- 온디바이스 가림 처리 속도. iPhone 15에서 송출 영상이 약 5.5fps였다(2026-10-12)
- 하트비트 실서버 수신, `stop_targets` 한도 종료, 입력 없음 5분 종료
- 백그라운드 정지 동안 하트비트 공백. iOS가 앱을 멈추면 보고가 끊긴다

원본 미리보기 트랙은 로컬 렌더링과 얼굴 등록에만 연결한다. PeerConnection에는
처리된 송출 트랙만 추가한다. 추론은 한 프레임씩 처리하고 밀린 프레임은 버린다.
카메라·회전·비식별화 설정 변경과 종료 시 이전 작업을 무효화한다. 모델 로드·추론·합성
오류에는 원본으로 대체하지 않고 영상 연결을 종료한다. 사용자가 비식별화를 끈 경우에만
원본 전송을 허용한다. 로컬 등록 변경 시 인식 목록과 추적 상태를 갱신한다.

프로토콜과 구형 서버 호환은 [AI 처리 계약](../contracts/api/ai-processing-v1.md)에 정의한다.
서버 얼굴 이름 저장은 서버 배포 뒤 적용된다. `server` 세션에서는 서버 AI 연결을 유지하고
추론 스위치만 바꾼다. 온디바이스 세션에서는 처리 방식을 바꿀 수 없고 새 세션이 필요하다.

## 검증

- iOS 시뮬레이터 전체 245개 테스트 통과(2026-09-21).
- 모드 협상: 명시적 응답, 구형 서버 AI 중지 확인, 불확실한 응답 차단, 세션 정리.
- 프레임: 동시 처리 제한, 중복 결과 차단, 설정·카메라 전환·종료 뒤 결과 폐기, 회전 복원.
- 서버 전체 `go test ./...` 통과. 모드 기본값·분리·유효성·이름 영속화 검증 포함.
- Debug 실기기 서명 빌드와 Release iOS 빌드(코드 서명 제외) 통과.
- 서버 세션·HTTP 테스트 `go test -race ./internal/session ./internal/server` 통과.

### iPhone 16 비공개 송출 검증 (2026-09-21)

기존 로그인 계정으로 일반 InnoLive 앱을 실행해 구형 서버 호환 경로를 검증했다.
서버 AI가 false임을 확인하고 온디바이스 처리된 720p 입력으로 비공개 방송을 준비했다.
라이브 상태에서 20초 동안 처리 프레임 600개, 원본 우회 프레임 0개를 확인했다.
이 수치는 로컬 송출 트랙에 전달한 프레임 수이며 YouTube의 수신 FPS 측정치는 아니다.
서버 응답은 publisher active와 server AI false를 유지했다.

종료 요청 성공 후 세션을 정리했다. YouTube Studio에서도 같은 제목·시각의 방송이
`Private`, `Live replay`, `Streamed`로 표시되는 것을 확인했다. 다시보기 처리 중이므로
완성된 녹화의 화질·블러 품질 평가는 이번 결과에 포함하지 않는다.

서버 #264의 코드는 아직 배포하지 않았다. 따라서 서버 이름 영속화와 AI 연결 자체를
생략하는 새 경로는 로컬 서버 테스트까지 확인했으며, 실기기 검증은 기존 서버의
세션별 비식별화 OFF 응답 확인 경로로 수행했다.

디버그 전용 `--private-on-device-broadcast-test`는 기존 로그인과 연결된 YouTube 계정을
사용한다. 서버가 비공개 설정을 확인한 뒤 준비·라이브 전환하고 20초 동안 처리 프레임 수와
송출 상태를 확인한 후 종료한다. 토큰·사진·임베딩은 내보내지 않는다. 명시적으로 승인한
테스트에만 이 실행 인자를 사용한다. 평상시 앱 실행에는 영향을 주지 않는다.

## 연결 유지 전환 후속 변경 (#287)

서버 AI OFF 응답을 받기 전에 로컬 비식별화를 활성화한다. 반대 방향에서는 서버 응답을
확인한 뒤 로컬 경로를 해제한다. 실패하면 보호 경로를 유지하고 방송 준비를 차단하며,
사용자가 같은 방식을 다시 눌러 재시도할 수 있다. 원본 미리보기는 두 모드 모두 별도
로컬 트랙을 사용하므로 화면 렌더러도 다시 연결할 필요가 없다.

자동 검증은 동일 세션의 왕복 전환, 실패 후 재시도, 응답 불일치, 초기화 중 늦은 응답,
이전 경로에서 처리하던 프레임 폐기를 포함한다. 전체 iOS 테스트 250개가 통과했다.

iPhone 16에서 서버 → 온디바이스 → 서버를 두 차례 왕복했다. 두 차례 모두 최초
세션 ID, PeerConnection 객체, 카메라 capturer 객체를 유지했고 connected 상태를
확인했다. 온디바이스 전환 후 5초 관찰 구간에 각각 104개·116개 처리 프레임을
전달했다. 로컬 원본 우회 프레임은 0개였다. 첫 로컬 전환은 준비와 서버 응답을
포함해 약 5.6초, 준비된 모델을 재사용한 두 번째 전환은 약 88ms였다. 단일 기기·
네트워크의 관찰값이며 일반적인 지연 보장은 아니다.

이번 검증에서는 YouTube 방송을 새로 만들지 않았다. 종료 시 테스트 세션을 정리했다.
서명 Debug 빌드와 Release 빌드(코드 서명 제외)도 통과했다.
