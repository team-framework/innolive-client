# iOS 홈 화면 카메라 스와이프

대상은 `apps/ios` 홈 화면의 카메라 입력 전환이다. HTTP, signaling, 다른 플랫폼 계약은 변경하지 않는다.

## 제스처 범위

세로 스와이프는 홈의 큰 영상 영역(`zoomableRemoteStream`)에만 붙인다. 위·아래 모두 제스처가 끝나는 시점에 한 번만 전환한다. 실제 세로 이동이 60pt 이상이고 세로 이동이 가로보다 클 때만 인식한다.

작은 원본 미리보기의 모서리 드래그와 기존 핀치 줌은 유지한다. `exclusively(before:)`로 핀치에 우선순위를 두고, 같은 터치에서 핀치와 스와이프가 함께 실행되지 않게 한다. 핀치 기준 배율은 `GestureState`에 저장해 종료하거나 취소하면 초기화한다.

전환 자체는 기존 전환 버튼과 같은 비동기 카메라 전환·롤백 경로를 사용한다.

## 기본 카메라 우선순위

다음 입력은 반대쪽 기본 내장 광각을 먼저 고른다. 그 장치가 없으면 같은 반대쪽의 다른 입력을 쓰고, 반대쪽이 없으면 목록에서 현재와 다른 입력을 고를 수 있다. 가상 줌 카메라 ID는 기존 catalog 해석으로 광각에 맞춘 뒤 같은 규칙을 적용한다. 설정 화면의 장치 목록·저장 동작은 바꾸지 않는다.

## 아무 동작도 하지 않는 조건

다음이면 캡처 전환, 선택값 저장, 오류 알림, 로딩 표시를 하지 않는다.

- 카메라 권한이 없거나 Simulator 고정 영상을 쓰는 경우
- 업링크 연결 또는 세션 준비가 진행 중인 경우
- 이미 홈·업링크 카메라 전환 중이거나 카메라를 해제하는 중인 경우
- 사용 가능한 입력이 없거나 하나뿐인 경우
- 현재 카메라 ID가 없어 반대 입력을 결정할 수 없는 경우
- 세로 스와이프 임계값을 넘지 않은 경우

버튼 `disabled`는 우회될 수 있으므로 같은 가능 여부 검사를 전환 동작에서도 적용한다.

## 검증 경계

단위 테스트는 입력 선택 규칙과 스와이프 방향·임계값을 확인한다. 실기기 전·후면 전환, 미리보기 드래그와의 공존, 핀치 종료 후 오인 전환 여부, 업링크 전환·해제 중 스와이프/버튼 무동작, Simulator 고정 영상에서 스와이프 시 무동작은 수동 확인 대상이다.

2026-09-13, Xcode 26.6 / iOS 26.5 Simulator에서 다음 43개 테스트가 모두 통과했다.

- `CameraDeviceCatalogTests`: 12개
- `CameraInputSwipeTests`: 2개
- `CameraZoomTests`: 12개
- `LocalPreviewSnapLayoutTests`: 15개
- `SimulatorVideoInputTests`: 2개

`generic/platform=iOS` 대상으로 Release 빌드도 성공했다. 기존 `CameraManager.zoomLimits(for:)` 동시성 경고 2건은 남아 있다. 실기기 터치 제스처와 송출 중 카메라 전환은 확인하지 않았다.
