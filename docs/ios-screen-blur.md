# iOS 전체 화면 블러

대상은 iOS 방송 컨트롤 UI와 서버 API 연동이다. 기존 비식별화 버튼 아래에
전체 화면 블러 버튼을 표시한다. 서버 처리 세션에서 연결을 유지한 채 PATCH를
요청하고, 응답의 `media.screen_blur_enabled`로 버튼 상태를 갱신한다.
영상 효과는 서버가 적용하며 iOS에서 별도 미리보기 필터를 덧씌우지 않는다.

요청 중에는 중복 토글 및 비식별화 동시 변경을 막는다. 실패하면 마지막 확인값과
기존 오류 배너를 유지하며 재시도할 수 있다. 세션 초기화 후 도착한 응답은 무시한다.
온디바이스 모드에서는 버튼을 비활성화한다. 블러가 켜져 있거나 요청 중이면 AI 처리
위치 변경을 막고, 블러를 끈 뒤 변경하도록 안내한다. 새 세션의 초기값은 꺼짐이다.

계약: [screen-blur-v1](../contracts/api/screen-blur-v1.md).

## 검증

`BroadcastSessionLifecycleTests`에서 인증 헤더와 경로, 켜기/끄기 응답 반영,
실패/필드 누락 시 값 보존, 초기화 이후 응답 무시, 온디바이스 비활성화를 검사한다.

실기기 확인 절차:
1. 서버 처리 모드로 방송을 준비하고 송출한다.
2. 블러를 켜서 미리보기와 실제 수신 화면 전체가 흐려지는지 확인한다.
3. 비식별화 켜짐/꺼짐 각각에서 블러가 유지되는지 확인한다.
4. 블러를 끄고 기존 비식별화 상태로 돌아오는지 확인한다.
5. 일시 중지/재개, 네트워크 실패 후 재시도, 세션 재생성 시 상태를 확인한다.
6. 온디바이스 모드에서 버튼 비활성화와 작은 화면의 버튼 배치를 확인한다.

자동 테스트와 빌드는 서버 배포 상태나 실제 송출 영상 검증을 대체하지 않는다.

2026-10-15 로컬 검증: iPhone 16 / iOS 27.0 Simulator에서
최신 main 기준 `BroadcastSessionLifecycleTests` 33개(블러 신규 4개 포함),
`BroadcastSessionStateTests` 10개, 총 43개 통과. 앱·테스트 번들 빌드 완료.
병렬 테스트 실행 지연 후 `-parallel-testing-enabled NO`로 재실행했다.
실기기 UI 및 실제 서버 송출 영상은 확인하지 않았다.
