# iOS 얼굴 원탭 등록

관련 이슈: client #586. 방송 화면에서 원본 카메라를 전체화면으로 띄우고, 얼굴을 탭하면 이름 입력 없이
그 사람의 블러를 해제한다. 서버 AI와 온디바이스 AI가 같은 등록 이미지를 쓴다. 서버 API와 multipart
형식은 그대로다. 계약: [reference-face-v1](../contracts/api/reference-face-v1.md).

설정 → 얼굴 관리의 기본 등록은 바꾸지 않았다. 이름을 먼저 입력하고, 가운데 영역의 한 얼굴을
3회 확인한 뒤 자동으로 등록한다.

## 동작

- 홈 화면 오른쪽 위 `영상 조절` 아래의 `얼굴 등록` 버튼을 누르면 가림 처리 전 원본 카메라가 전체화면으로 뜬다.
  방송 준비 전에는 카메라 미리보기를, 방송 중에는 송출 경로와 분리된 원본 미리보기 트랙(`rawPreviewTrack`)을 쓴다.
  이 화면은 기기에만 보이고 송출 영상은 바뀌지 않는다.
- 앱은 0.1초마다 프레임 전체에서 Vision으로 얼굴을 찾는다. 원본 기준 얼굴 짧은 변이 100px 이상이고
  중심이 전체화면 미리보기 안에 있는 얼굴에만 모서리 브라켓과 `탭해서 등록`을 그린다.
  작은 얼굴에는 아무것도 그리지 않고 탭도 받지 않는다.
- 브라켓을 탭하면 앱이 그 프레임을 멈추고 고른 얼굴만 밝게 남긴 채 바로 등록한다. 이름은 앱 언어의
  월·일·시와 `게스트`를 붙여 만든다. 예: `10월 17일 오후 3시 - 게스트`.
- 성공하면 완료 표시를 0.8초 보여 준 뒤 전체화면을 닫는다. 실패하면 멈춘 화면에 오류와 `다시 선택`,
  `다시 시도`를 띄운다.
- 현재 AI 설정의 저장소(서버 또는 이 기기)에 등록한다. 카메라 권한이 없거나 카메라 전환 중이거나 방송
  카메라가 아직 프레임을 넘기지 못하면 버튼을 끈다.
- 동작 줄이기를 켠 기기에서는 브라켓이 깜빡이지 않는다.

## 등록 이미지

- 앱은 고른 얼굴 박스의 중심에서 긴 변의 2배 크기 정사각형을 자른다. 얼굴 인식 모델이 쓰는
  1.5배 정사각형이 이 안에 들어간다. 프레임 밖은 검정으로 채운다.
- 자른 이미지를 500x500으로 줄이고 JPEG 품질 0.9로 인코딩한다. 원본 짧은 변이 500px보다 작으면
  등록하지 않는다.
- 서버와 온디바이스 등록은 얼굴이 2개 이상인 이미지를 거부한다. 앱은 다른 얼굴 박스를 1.3배로 넓혀
  검게 칠하고, 고른 얼굴 영역은 원본으로 다시 덮는다.
- 전체 프레임에서 놓친 작은 얼굴이 확대한 이미지에서 잡힐 수 있다. 앱은 자른 이미지에서 얼굴을 다시
  찾아 가운데 얼굴 외의 얼굴을 같은 방식으로 가린다. 가운데 얼굴 하나만 남아야 올린다.
- 감지와 미리보기는 같은 방향의 이미지를 쓴다. 전면 카메라는 미리보기처럼 좌우 반전한 이미지에서 찾는다.

## 검증

시뮬레이터의 Vision은 기본 추론 장치를 만들지 못한다(`Could not create inference context`).
시뮬레이터 빌드에서만 얼굴 요청을 CPU로 실행한다.

`FaceSelectionTests`가 가시 영역, aspect-fill 좌표, 선택 조건, crop 크기, 가림과 검정 채움 픽셀,
공개 이미지 fixture 등록, 전면·후면 카메라 좌표를 검사한다. fixture 테스트는 세로 캔버스에 큰 얼굴 2개와
작은 얼굴 1개를 놓는다. 작은 얼굴은 왼쪽 얼굴의 등록 이미지 범위 안에 있다. 테스트는 큰 얼굴마다 만든
등록 이미지가 YuNet 등록 조건(점수 0.9 이상, 얼굴 1개, 40px 이상)을 통과하는지 확인한다. 서버도 같은
YuNet 가중치와 문턱을 쓴다.

2026-10-17 iPhone 17 시뮬레이터에서 전체 프레임 Vision은 약 70px 작은 얼굴을 찾지 못했다. 재검출을
넣기 전에는 로컬 확인이 그 등록 이미지를 거부했다. 재검출 뒤에는 작은 얼굴이 가려졌고 YuNet 점수
0.917로 통과했다. 같은 공개 이미지를 복제한 합성 장면이며 실제 다인 인식 정확도를 뜻하지 않는다.

`IOSCompatibilityRenderingTests`가 브라켓 배치, 선택 화면, 홈 화면 버튼 열을 라이트·다크로 캡처한다.
`FaceSelectionTests`는 전체화면 비율의 선택 영역과 자동 게스트 이름도 검사한다. 기존 얼굴 관리 화면의
이름 칸 렌더링 검사는 그대로다.

fixture는 Git에서 제외한다. 없으면 fixture 테스트 2개를 건너뛰고, Core ML 모델이 없으면 YuNet 확인만 생략한다.

```sh
mkdir -p apps/ios/InnoLive/InnoLiveTests/PrivacyFaceFixtures
curl -L --fail -o apps/ios/InnoLive/InnoLiveTests/PrivacyFaceFixtures/face-selection-sample.jpg \
  https://raw.githubusercontent.com/opencv/opencv/4.x/samples/data/lena.jpg
# SHA-256 7de7ed51a1594fff247f4cae2301eceacf5313d6011e37b4a4c8733f7bb72c07
```

## 실기기 확인

- 원본 전체화면에서 전면·후면 카메라 브라켓과 얼굴 위치 일치
- 방송 준비 전과 방송 중 원탭 등록, 자동 게스트 이름, 화면이 닫힌 뒤 블러 해제
- 여러 명 중 고른 사람만 등록
- 서버 모드 업로드와 온디바이스 모드 저장
- 설정 → 얼굴 관리의 기본 등록이 이전과 같게 동작
