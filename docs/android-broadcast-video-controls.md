# Android 방송 영상 조절

## 사용자 동작

방송 화면의 `영상 조절` 버튼을 누르면 Material 3 하단 시트가 열린다.
노출은 -2~+2 EV 안에서 현재 카메라가 지원하는 단계로 적용한다. 화면에는
실제 적용된 EV를 표시한다. 색온도는 -1~+1, 채도는 0~200%이며,
초기화하면 노출 0 EV, 색온도 중립, 채도 100%로 돌아간다.
설정은 기기에 저장해 다음 실행에도 유지한다. 초기화는 손떨림 보정 선택을 유지한다.

| 프리셋 | 노출 | 색온도 | 채도 |
| --- | --- | --- | --- |
| 선명하게 | 0 EV | -0.20 | 140% |
| 화사하게 | +0.8 EV | +0.20 | 120% |
| 따뜻하게 | +0.2 EV | +0.60 | 110% |

프리셋 수치는 iOS PR #322와 같다. 카드에는 현재 색감 처리 전 카메라 입력을
각 프리셋으로 바꾼 미리보기를 표시한다. 원본 입력의 실제 노출을 기준으로
프리셋 노출 차이를 시뮬레이션하므로, 하드웨어의 노출 전환이나 제한에 따라
송출 결과와 차이가 날 수 있다. 전면 카메라 미리보기는 좌우를 반전한다.
방송 연결 전에도 미리보기를 사용할 수 있다.

`카메라 및 오디오`의 손떨림 보정 스위치는 기본으로 켜져 있다.
현재 적용 중, 미지원, 적용 상태 확인 중, 카메라가 켜지면 적용, 꺼짐을 구분한다.
화면 문구는 한국어·영어·일본어를 제공한다.

## 캡처와 송출

CameraX의 같은 Preview/ImageAnalysis 세션에서 자동 노출을 유지하며 EV를 조절한다.
Camera2가 지원한다고 알린 모드 중 Android 13 이상에서는 미리보기 보정 모드를
우선하고, 표준 동영상 보정을 다음으로 선택한다. 현재 세션에서 미리보기 보정이
꺼진 채 반환되거나 요청에 실패하면 표준 모드를 시도한다. 적용 여부는 요청값만으로
판단하지 않고 캡처 결과의 실제 모드로 확인한다. 해상도와 FPS를 자동으로 바꾸지 않는다.
카메라를 해제하면 적용 상태를 초기화하고, 다시 바인딩할 때 설정을 재적용한다.

색온도와 채도는 WebRTC로 보내기 전 I420 프레임의 U/V 채널에 lookup table로
적용한다. Y 채널은 카메라 노출 결과를 유지한다. Android YUV 변환과 iOS Core Image의
색변환 수학은 서로 다르므로 기기 간 픽셀 일치를 보장하지 않는다. 서버 비식별화 경로의
송출과 연결 중 작은 미리보기는 같은 로컬 VideoTrack을 사용한다. 연결 전 큰 미리보기는
CameraX 원본을 표시한다. 색 처리 실패 시 해당 프레임을 버린다.

프리셋 미리보기는 시트를 열었을 때만 생성한다. 캡처 콜백은 원본 YUV를 복사하고,
별도 작업 스레드가 축소·색변환·회전을 수행한다. 동시에 한 작업만 허용하고 초당 최대
8장, 긴 변 최대 480픽셀로 제한한다. 시트를 닫거나 캡처를 해제하면 이전 작업 결과를
게시하지 않는다. 연결 전 미리보기는 WebRTC JNI 초기화 없이 동작한다.

HTTP와 WebRTC signaling 필드는 변경하지 않는다.

## 검증 범위

- JVM 테스트: 설정 정규화, 프리셋 수치, 노출 단계와 지원 범위, 보정 모드 선택,
  YUV 변환, 미리보기 빈도와 생명주기.
- Android 계측 테스트: 설정 저장·복구, 실제 Bitmap/I420 프레임 처리, Compose 조작,
  CameraX 원본 프리셋 미리보기.
- 실제 흔들림, 화각, 송출 FPS, 지연과 발열은 실기기와 수신 영상으로 검증한다.
  동일 카메라·해상도·네트워크에서 보정 켬/끔 보행 촬영을 비교하고,
  추가 지연 200ms 이내와 FPS 저하 10% 이내를 확인한다. 에뮬레이터 통과만으로
  이 기준을 충족했다고 판단하지 않는다.
