# 랜딩 페이지 간격과 스크롤

대상은 `apps/landing`의 Web UI다. HTTP API와 WebRTC 계약에는 영향이 없다.

## 상단 간격

- 공통 고정 헤더의 높이와 콘텐츠가 확보하는 높이는 `--header-height: 6rem`을 사용한다.
- 검색 안내, 사용 가이드, 가격, 체험 안내, 개인정보 처리방침, 이용약관, 고객 지원은 `page-top-spacing`으로 헤더 아래에 `2rem`을 둔다.
- 검색 안내의 첫 콘텐츠는 경로 표시다. 다른 페이지는 제목부터 시작한다.
- 문서의 언어·문서 메뉴는 표시하지 않는다. 언어는 공통 헤더에서 바꾸고, 문서는 푸터 링크로 이동한다.
- 홈의 인트로·섹션 배치와 로그인 화면의 중앙 정렬은 각 화면의 기존 간격을 사용한다.

## 페이지 이동

- `RouteScrollReset`은 경로가 바뀌면 스크롤을 `(0, 0)`으로 이동한다.
- 브라우저의 스크롤 복원을 `manual`로 설정하므로 뒤로·앞으로 이동해도 페이지 맨 위에서 시작한다.
- 이동한 URL에 해시가 있으면 해당 앵커로 이동한다. `#main`으로 이동한 문서와 가이드의 본문은 키보드 포커스를 받는다.
- 홈의 `ScrollSmoother`는 `ScrollTrigger`가 높이를 다시 계산하면 해시 위치도 다시 맞춘다.

## 확인 방법

- 데스크톱과 모바일에서 고정 헤더의 하단부터 첫 콘텐츠까지의 간격을 비교한다.
- 스크롤한 안내·문서·홈에서 다른 페이지로 이동한 뒤 `scrollY`가 `0`인지 확인한다.
- 뒤로·앞으로 이동, 헤더의 언어 전환, 푸터의 FAQ 링크, 본문 건너뛰기 링크를 확인한다.
- 한국어·영어·일본어 문서에 중복 메뉴가 없는지 확인한다.
- `apps/landing`에서 빌드, ESLint, 구조화 데이터·다국어 테스트와 `scripts/check-aeo.py`를 실행한다.
