# iOS 이메일 인증 화면

대상은 `apps/ios`의 이메일 로그인, 회원가입, 인증 코드 입력 화면이다. 서버 API,
토큰 저장 방식, 이메일 및 비밀번호 검증 규칙은 기존 `AuthSession`을 사용한다.

## 화면과 입력 흐름

- 이메일 인증에 진입하면 이메일과 비밀번호를 함께 입력한다.
- 회원가입으로 전환할 때 이메일은 유지하고 비밀번호와 확인 입력은 비운다.
- 회원가입 화면에서도 이메일을 수정할 수 있다. 인증 메일을 보내면 수신 주소와
  6자리 코드 입력란을 표시한다.
- 인증 화면에서 뒤로 가면 진행 중인 가입을 취소하고 회원가입 화면으로 돌아간다.
- 코드 재전송에 성공하면 기존 코드 입력을 비우고 재전송 완료를 안내한다.
- 요청 중에는 입력, 제출, 단계 전환을 비활성화하고 제출 버튼에 진행 상태를 표시한다.

## 표시와 접근성

- 화면 위쪽에 제목, 설명, 입력란, 주요 버튼 순서로 배치한다. 입력란에는
  값이 있어도 사라지지 않는 레이블을 표시한다.
- 입력란은 시스템 배경색을 사용하고, 주요 동작은 전체 너비의 기본 Glass 버튼을
  사용한다. 소셜 로그인 화면은 기존 배치를 유지한다.
- 시스템 글꼴과 의미 기반 색상을 사용한다. 큰 글씨와 키보드로 공간이 줄어들면
  내용을 스크롤할 수 있다. 키보드의 다음 버튼으로 입력란을 이동하고 완료로 닫는다.
- 비밀번호 보기 버튼은 입력란마다 독립적으로 작동한다. 화면을 전환하면 숨김 상태로
  되돌린다. 이메일·비밀번호 자동 완성과 인증 코드 자동 입력을 지원한다.
- 이메일 형식 오류는 입력란을 벗어난 뒤 표시한다. 비밀번호 길이와 일치 여부는
  입력 중 확인하고, 불일치 오류는 확인 입력란을 벗어난 뒤 표시한다.
- 비밀번호 길이는 UTF-8 기준 8~72바이트라는 기존 규칙을 따른다. 화면에서는
  영문·숫자 기준으로 길이를 안내한다. 서버 오류와 코드 재전송 완료는 VoiceOver로 알린다.

## 수동 확인

1. 소셜 로그인 화면에서 이메일 로그인을 열고 이메일, 비밀번호, 버튼 배치를 확인한다.
2. 잘못된 이메일 입력 후 다음 입력란으로 이동한다. 안내가 나타나고 주소를 고치면 사라져야 한다.
3. 회원가입으로 전환해 이메일 유지와 비밀번호 초기화, 보기·가리기, 길이·일치 안내를 확인한다.
4. 가입 요청, 코드 오류, 재전송, 인증 완료는 테스트용 인증 API 또는 승인된 테스트 계정으로 확인한다.
5. 라이트·다크 모드, 접근성 글자 크기, 키보드가 열린 상태에서 잘림과 버튼 접근성을 확인한다.
