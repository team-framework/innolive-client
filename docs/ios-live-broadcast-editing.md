# iOS 방송 정보 수정

라이브인 대상의 상태 영역과 기존 방송 설정 화면에서 플랫폼별 ‘방송 정보
수정’을 연다. 방송 준비 폼의 Liquid Glass 카드·제목·설명·카테고리·태그
입력과 저장 버튼을 재사용한다. 라이브 편집에는 플랫폼 전환·직전 값 적용을
제공하지 않는다. 공개 범위·시청자층은 표시하되 잠근다. 썸네일 변경은
허용하지 않으며 PATCH에도 포함하지 않는다.

## 저장과 수명주기

- 편집 초안과 방송 준비 초안을 분리한다. 실패 시 입력을 보관한다.
- 성공하면 해당 플랫폼의 표시값·로컬 설정을 갱신한다. 방송·세션·카메라를
  재시작하지 않는다. 저장 중 입력·버튼과 다른 대상 편집 진입을 잠근다.
- targets가 있으면 대상별 live를 기준으로 한다. 명시적 빈 targets는
  기존 stream으로 대체하지 않는다. 기존 서버의 단독 stream은 YouTube로
  처리한다. 종료·방식 전환·제어 요청 중에는 수정할 수 없다.
- 세션·계정·채널·편집기 세대가 바뀐 응답은 적용하지 않는다. 늦은 PATCH
  응답으로 새 폴링 상태나 다른 플랫폼의 종료 상태를 되돌리지 않는다.
- broadcast_not_live 이후 조회가 실패해도 해당 대상 편집을 잠근다.
  같은 세션에서 종료된 대상이 다시 live로 전환되면 편집을 다시 허용한다.

## 검증 경로

`LiveBroadcastEditingTests`는 URLProtocol 응답으로 실제 API·편집기·통합
객체를 실행한다. 허용 필드·대상·인증, 입력 검증, 실패 후 재시도, 중복 요청,
비라이브 차단, 늦은 응답, 인증 갱신을 확인한다. 실제 플랫폼 검증과 구분한다.

Debug 실행 인자:

- `--live-broadcast-edit-preview`: 합성 응답으로 실제 YouTube 폼을 확인한다.
- `--live-edit-chzzk`: 위 인자와 함께 치지직 폼을 확인한다.
- `--live-edit-failure`: 위 인자와 함께 첫 저장 실패·두 번째 성공을 확인한다.
- `--live-broadcast-edit-test`: 기존 앱 인증·YouTube 연결·저장된 시청자층으로
  비공개 방송을 시작하고 제목·설명·카테고리를 수정한다. 서버 저장값·LIVE·
  publisher_active·세션·PeerConnection·시작 시각 유지와 10초 후 상태를
  확인하고 방송·세션을 종료한다. 인증이 없으면 송출 전에 중단한다.

실제 검증 결과는 PR의 확인 방법에 기록한다. 시뮬레이터의 합성 응답 확인은
실제 카메라·플랫폼 수신 영상/오디오를 입증하지 않는다. 치지직 OAuth와
복수 대상 선택은 선행 작업이며 두 플랫폼 실제 통합 검증에는 이 구현이
필요하다.
