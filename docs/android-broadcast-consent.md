# Android 방송 영상·음성 전송 동의와 플랫폼 전송 안내

관련 작업: [Issue #523](https://github.com/team-framework/innolive-client/issues/523). iOS 기준은 [iOS 동의 흐름](ios-consent-flow.md)이다.

## 표시 조건과 순서

방송 설정 창에서 **방송 준비**를 확정하면, 입력 검증을 통과한 뒤 카메라·마이크 권한 확인과 서버 연결보다 먼저 저장된 동의를 확인한다. 없는 항목만 아래 순서로 연다.

1. 방송 영상·음성 전송 동의: 송출 대상과 관계없이 항상 필요
2. YouTube 전송 안내: 송출 대상에 YouTube가 있을 때
3. 치지직 전송 안내: 송출 대상에 치지직이 있을 때

동시 송출은 세 화면을 순서대로 연다. 한 항목을 수락하면 다음 항목을 이어서 열고, 모두 수락하면 기존 권한 확인과 방송 준비를 진행한다.

## 화면 동작

- 본문 끝까지 스크롤하면 확인 버튼을 켠다. 본문이 한 화면에 들어오면 바로 켠다. 다시 위로 올려도 켜진 상태를 유지한다.
- 접근성 이동 등으로 마지막 항목인 개인정보처리방침 전문 링크가 화면에 모두 보여도 끝까지 읽은 것으로 본다.
- 스크롤이나 전문 링크 열람만으로는 수락하지 않는다. 버튼을 눌러야 기록한다.
- 취소·바깥 탭·뒤로가기는 방송 설정 창으로 돌아가고 연결하지 않는다. 단계마다 새 창으로 열어 스크롤·확인 상태를 초기화한다.
- 개인정보처리방침 전문 보기는 앱 언어(ko·en·ja, 그 외 ko)의 `https://innolive.studio/<언어>/privacy`를 외부 브라우저로 연다. 설정 화면의 링크와 같은 주소다.

## 문구

- 영상·음성 전송 동의와 YouTube 전송 안내는 iOS 문구(ko·en·ja)를 그대로 사용한다.
- 치지직 전송 안내는 YouTube 안내와 같은 구성으로, 개인정보처리방침 7항의 치지직(CHZZK)/NAVER 항목 범위만 요약한다. 방침에 없는 연결 토큰 암호화 문장은 넣지 않는다.
- 영문·일문 개인정보처리방침에는 아직 치지직 항목이 없다.

## 기록 수명

- 수락 기록은 기기 SharedPreferences `innolive_broadcast_consent`에 버전이 있는 키로 남긴다. 서버 동의 이력은 만들지 않는다.
- 로그아웃·로그인 만료·앱 재실행 후에도 유지한다.
- 계정 삭제의 로컬 정리 단계에서 모든 기록을 지운다.
- 서버 계정 조회에서 YouTube 또는 치지직 연결이 없음을 확인하면 해당 플랫폼 안내 기록만 지운다.

## 차단

`WebRtcSessionViewModel`의 방송 준비 요청도 필요한 기록이 없으면 서버 연결 전에 거부하고 상태 문구를 표시한다. 화면을 거치지 않은 호출도 카메라·마이크를 서버에 연결하지 않는다. 방송 중 화면과 세션 복구 흐름은 바꾸지 않았다.

## 구현 위치

- `feature/live/consent/BroadcastConsent.kt`: 단계 순서와 기록 저장소
- `feature/live/consent/BroadcastConsentDialog.kt`: 동의·안내 창
- `feature/live/Live.kt`: 방송 준비 확정 시 단계 진행
- `app/MainActivity.kt`, `feature/login/account/AccountLocalDataCleaner.kt`: 기록 초기화
