# iOS 방송 전환과 원본 저장

## 범위와 현재 구현

대상은 iOS의 방송 UI, 미디어 입력, 로컬 저장이다. HTTP·WebRTC 서버 계약은 변경하지 않는다.

`BroadcastLifecycle`은 준비, 카운트다운, 시작 요청, 방송, 종료 요청, 결과의 클라이언트 상태를 관리한다.
`BroadcastRecordingState`는 녹화 대기, 입력 수신, 파일 마무리, 저장 성공, 실패를 따로 관리한다.
준비 오버레이·시작 카운트다운·종료 결과 화면을 방송 경로에 연결했다. 카메라 원본 입력을 녹화하고 마지막 대상 종료 시 자동 저장한다.

## 전이와 호출 규칙

- 준비 시작 시 `beginPreparation`, 성공·실패 시 같은 generation으로 `finishPreparation`을 호출한다.
- 준비 완료에서 `beginCountdown`을 호출한다. 호출자는 각 숫자를 1초 표시하고 `advanceCountdown`을 호출한다. 숫자 1의 표시 시간이 끝나면 `beginStarting`을 호출한다.
- 취소 시 `cancelCountdown`을 호출한다. 화면 이탈, 백그라운드 이동, 세션 교체 시 실행 중인 타이머도 취소한다. 세션 교체·로그아웃은 `reset`으로 이전 generation을 무효화한다.
- `beginStarting` 성공 직후 녹화기를 준비하고 golive를 요청한다. 카운트다운을 제외하고 요청 직전부터 카메라 원본 입력을 기록한다.
- 실제 응답을 반영한 뒤 `reconcileTargets`에 활성 대상 집합을 전달한다. live·paused·재연결 중인 live 대상을 포함하고, prepared 대상은 제외한다. 상태 조회 실패를 빈 집합으로 바꾸면 안 된다.
- 시작 중 빈 집합은 아직 시작을 확인하지 못한 상태다. 전체 시작 실패를 확인한 경우 `startFailed`로 돌아간다. 일부 대상이 성공했다면 해당 대상 집합으로 방송 상태를 유지한다.
- 종료 요청 전 `beginEnding`, 응답 적용 후 `finishEnding`을 호출한다. 남은 대상이 있으면 방송과 녹화를 유지한다. 마지막 활성 대상 종료를 확인하면 결과와 파일 마무리 상태로 전환한다.
- 서버 자동 종료는 확인된 상태를 `reconcileTargets`에 전달한다. 기존 prepared 연결을 유지하는 것과 실제 방송 종료를 구분한다.
- 녹화 실패는 방송 상태를 바꾸지 않는다. 파일을 닫고 재생 가능 여부를 확인한 후에만 `recordingSaved`를 호출한다.

## 녹화 구간과 저장 정책

녹화기는 카운트다운을 제외하고, golive 요청 직전부터 마지막 활성 대상 종료 확인까지 비식별화·색상 보정 전 카메라 프레임과 기존 송출 경로의 음성을 기록한다. 응답을 받은 뒤 녹화를 시작하면 서버가 먼저 공개한 구간을 놓칠 수 있으므로 요청 시점에 임시 녹화를 시작한다. 따라서 파일 앞부분에는 요청부터 공개 확인까지의 짧은 구간이 포함될 수 있다. 전체 시작 실패 시 임시 파일을 삭제한다. 모델은 실패 generation의 늦은 콜백을 무시하며 실제 파일 삭제는 녹화기가 담당한다.

원본은 서버·온디바이스 AI 처리와 앱의 노출·색온도·채도 보정 전 카메라 입력이다. 방송 방향 잠금과 카메라 방향에 따른 회전 정보는 유지한다. AI 모델 실패나 송출 경로 전환 중에도 녹화기가 연결된 동안 카메라 입력을 기록한다. 송출 경로의 비식별화 정책은 유지하며 원본을 직접 송출하지 않는다. 기존에 저장한 처리 후 영상은 복원하지 않는다.

기본 내보내기는 음성이 포함된 MP4다. 추가 내보내기는 무음 MP4와 M4A 두 파일이다. 앱 내부 저장과 사진 앱·파일 앱 내보내기 성공을 구분한다. 저장·분리 내보내기·복구 정책과 검증 범위는 아래에 기록한다.

## 검증

`BroadcastLifecycleTests`는 취소 뒤 늦은 작업, 중복 시작 방지, 전체 시작 실패, 일부 대상 종료 실패, 마지막 대상 종료, 저장 실패 분리, 새 세션의 이전 결과 거부를 검증한다. 이 테스트는 API·기기 녹화 성공을 증명하지 않는다.

화면·미디어 검증은 iPhone 16과 iPhone 16 Pro에 항목을 나누어 진행했으며, 최종 통합 검증은 iPhone XR에서 수행했다. iOS 26 이상은 기존 Liquid Glass를, iOS 18은 동일 컴포넌트의 material fallback을 사용한다.

### 시작 화면 검증

2026-10-17 iPhone 16 실기기에서 상태 모델·방향 잠금·카운트다운·시작 화면 렌더링 테스트 28개가 통과했다. 카운트다운은 취소·백그라운드 이동·세션 교체·중간 종료 응답 이후 golive를 실행하지 않는다. 밝음·어두움·가로·세로·큰 글씨 20개 화면 조합을 렌더링하고 첨부 이미지로 확인했다. API 동작은 URLProtocol fixture로 검증하며 실제 플랫폼 방송 성공과 구분한다.


## 종료 UI 구현

전체 방송 종료는 네이티브 확인창을 거친다. 유효한 종료 요청을 시작한 뒤 진행 화면을 표시하며, 응답에 남은 live·paused 대상이 있으면 방송 화면으로 돌아가 오류를 보여준다. 플랫폼 하나만 종료해도 다른 대상이 방송 중이면 결과 화면으로 전환하지 않는다. 마지막 대상 종료를 확인하면 방송 시간과 닫기 버튼을 표시한다.

로컬 업링크 종료나 복구 실패는 기기 송출 중단과 플랫폼 종료 확인을 구분한다. 원격 종료를 확인하지 못하면 결과 제목을 기기 송출 중단으로 표시하고 확인이 필요한 이유를 함께 보여준다. 결과 화면을 닫아도 lifecycle generation을 유지해 후속 녹화기 콜백을 받을 수 있다.

종료 화면은 녹화기의 저장 중·저장 완료·실패 상태를 표시한다. 검증된 파일이 있으면 재생·내보내기 버튼을 활성화한다. 전체 종료 확인창의 실제 탭 검증과 기기 실행 결과는 구분해서 기록한다.

검증: iPhone 16에서 모델·통합 테스트 32개와 종료 화면 렌더링 테스트 3개 통과. 밝은/어두운 화면, 큰 글자, 저장 상태별 13개 화면 첨부 확인. 실제 서버 종료 요청과 확인창 직접 탭은 이 검증에 포함하지 않는다.

## 송출 미디어 녹화

`LocalBroadcastRecorder`는 카메라 원본 프레임과 마이크 PCM을 H.264 + AAC 48 kHz stereo MP4에 기록한다. 카메라 relay는 방향 잠금을 적용한 직후, 색상 보정과 AI 처리 전에 pixel buffer·rotation·timestamp를 녹화기에 전달한다. 서버·온디바이스 모드가 같은 녹화 입력 경로를 사용한다. 녹화 시작·종료는 coordinator의 sink 연결·해제로 제어한다.

WebRTC 마이크는 기본 audio device module의 capture postprocessing callback에서 복사한다. LiveKit의 FloatS16을 Float32로 정규화하며, mono는 두 채널로 복사한다. `capturePostProcessingDelegate`는 audio processing module 생성 후 setter로 연결한다. 초기화 인자만 전달하면 현재 의존성의 native adapter가 callback을 연결하지 않는다. 별도의 마이크 장치를 열거나 audio session의 manual 설정을 바꾸지 않는다.

직접 송출 모드에서는 기존 microphone callback의 PCM과 host time을 사용한다. 대상이 모두 일시 중단된 동안에는 같은 길이의 무음을 저장한다. 공통 입력 녹화 한 개를 유지하므로 플랫폼별 pause slate 등 downstream 변형은 포함하지 않는다.

녹화기는 첫 영상 크기를 유지하고 카메라 방향·크기 변경 시 비율을 유지해 맞춘다. 영상 대기는 4개, 음성 대기는 200개 버퍼·96,000프레임 중 먼저 도달하는 한도로 제한한다. 영상 writer 지연은 누락 수로 집계하고, 음성 한도 초과와 인코더 오류는 실패 callback을 한 번 전달한다. 음성 writer의 일시적인 대기는 queue에서 처리하며 종료 시 최대 15초 동안 남은 음성을 마무리한다. 캡처 공백에는 무음을 넣어 시간축을 유지한다.

WebRTC 음성 callback에는 하드웨어 timestamp가 없어 첫 host time과 누적 sample 수로 시간축을 만든다. 긴 입력 공백은 host time으로 다시 맞춘다. 파일 트랙 시간 비교와 실제 영상·음성 내용의 동기 검증은 별도 검증 항목이다.

검증: iPhone 16 Pro에서 녹화기 8개·실제 마이크 녹화 1개·기존 직접 송출/relay 회귀 38개 테스트 통과. 실제 마이크 녹화 파일은 8.030초, 영상 끝 8.023초, 디코딩된 음성 385,440프레임, peak 0.0501, RMS 0.00126, clipping 0%. 새 녹화기 교체 후 이전 파일 바이트 불변 확인. 해당 테스트의 영상은 음성 경로 분리 검증용 합성 프레임이며 실제 카메라·콘텐츠 동기는 별도 기기 검증 대상이다.

## 자동 저장과 보관함

첫 라이브 요청 직전에 녹화기를 연결하고, 추가 플랫폼은 같은 녹화기를 공유한다. 확인된 마지막 대상이 종료되면 sink를 먼저 해제하고 writer 종료·파일 검증·이동·메타데이터 저장을 순서대로 실행한다. 라이브 시작을 확인하지 못한 요청은 임시 파일을 폐기한다. 연결 장애로 로컬 캡처를 종료한 경우에는 확인된 방송의 원본을 저장하며 결과 화면에 원격 종료 미확인 안내를 유지한다.

저장 위치는 앱 Application Support의 Recordings다. `.partial.mp4`로 기록한 뒤 재생 가능 여부와 영상·음성 sample 디코딩을 확인하고 최종 `.mp4`로 이동한다. JSON 메타데이터는 원자적으로 기록하며 메타데이터 누락 파일은 보관함을 다시 열 때 복구한다. 완료하지 못한 partial은 저장 성공 목록에 표시하지 않는다. 완성 파일의 이동·메타데이터 저장 실패만 재시도할 수 있고, writer 실패는 재시도 버튼을 표시하지 않는다.

결과 화면을 닫아도 저장을 계속하고, 저장된 방송 목록에서 파일을 재생할 수 있다. 준비·방송 중에는 재생으로 송출 오디오에 영향을 주지 않도록 보관함 진입을 제한한다. 녹화 실패는 배너와 결과 상태로 알리며 방송 요청을 실패시키지 않는다. 새 방송을 시작하면 이전 저장 callback은 새 화면을 갱신하지 않는다.

검증: iPhone 16에서 coordinator 8개·저장소 5개·방송 통합 25개 테스트 통과. 다중 대상 공유, 마지막 종료, 미확정 시작 폐기, 빈 입력 실패, 저장 공간 부족, 저장 재시도, 새 방송과 이전 최종화 겹침 검증.

저장목록·결과·플레이어·저장 중·재시도 화면 렌더링 테스트 3개 추가 통과. 큰 글자와 고대비를 포함한 8개 화면 생성 및 대표 화면 확인.

## 내보내기

기본 형식은 음성을 포함한 원본 MP4다. 원본 파일의 바이트와 URL을 유지하고 시스템 공유 화면을 통해 파일 앱 등으로 내보낸다. 분리 형식은 영상만 담은 MP4와 음성만 담은 M4A이며, 원본의 각 트랙 시간축·회전 정보를 유지한다. 가능한 경우 passthrough로 복사하고, M4A가 해당 AAC media를 지원하지 않는 오류에 한해 AAC 내보내기로 재시도한다. 영상·음성의 끝 시각이 다르면 각 원본 트랙 길이와 비교해 검증한다.

실패·취소 시 해당 작업의 UUID 임시 디렉터리만 정리한다. 성공한 공유 파일은 확장 프로그램이 계속 읽을 수 있으므로 즉시 삭제하지 않는다. 앱 cold start에서 전용 marker와 UUID가 일치하는 24시간 이상 지난 export만 정리하며 원본·최근 파일·symlink는 보존한다.

사진 앱 저장은 사용자가 선택했을 때 add-only 권한을 요청하고 Photos 완료 callback 성공 후에만 저장 완료를 표시한다. 공유 화면을 열거나 닫은 사실만으로 파일 앱 저장 성공을 표시하지 않는다.

검증: iPhone 16에서 exporter 5개·화면 렌더링 2개 테스트 통과. 원본 바이트 보존, 영상·음성 트랙 분리와 서로 다른 종료 시각, 부분 파일 생성 후 취소·실패, 오래된 임시 파일 정리 검증. 원본 공유·사진 저장 버튼 및 큰 글자 화면 5개 생성과 대표 화면 확인. 실제 Files destination 선택·Photos 저장 완료는 미검증.

## 저장 중단과 복구

저장 종료·재시도는 UIKit background task를 확보한다. OS가 시간을 회수하면 저장 실패와 재시도 불가 상태를 표시한다. 같은 writer가 아직 마무리 중이므로 중복 종료를 요청하지 않는다. 이후 실제 파일 검증이 성공하면 저장 완료로 바꾼다. 이전 방송의 만료·완료 콜백은 새 방송의 상태를 변경하지 않는다.

녹화별 journal은 시작 대기·방송 확인·최종화·writer 완료·실패·폐기를 구분한다. 보관함은 방송을 확인한 세션의 남은 partial에 한해 영상·음성 전체를 디코딩하고, 검증 전후 크기·수정 시각이 같으면 최종 파일로 복구한다. 활성 writer의 경로는 symlink를 해석해 제외한다. 확인할 수 없는 파일은 삭제하지 않고 보관 개수를 안내한다. 이 복구는 iOS가 중단된 MP4의 구조를 완성해 준다는 보장이 아니다.

자동 저장에는 Photos 권한이 필요 없다. 사진 앱 저장은 별도 사용자 동작이다. 용량 조회 실패·공간 부족은 녹화 실패로 표시하고 방송 시작 요청을 계속할 수 있다. 검증에서 사용한 공간 부족은 용량 조회 주입이며 기기의 저장소를 실제로 채우지 않는다.

## iOS 18과 단일 카메라 호환성

XR 실기기에서 상태 모델·방송 설정 객체를 해제할 때 `swift_task_deinitOnExecutorMainActorBackDeploy`에서 malloc 오류가 발생했다. 기존 [iOS 18 객체 해제 규칙](ios-version-support.md)에 맞춰 새 MainActor 객체와 테스트 fixture에 빈 `nonisolated deinit`을 명시했다. 실제 crash stack에 `BroadcastSettingsEditor.__deallocating_deinit`이 포함됐으며 수정 후 해당 동기 상태 테스트와 설정 화면 렌더링이 통과했다.

또한 XR 전면 1280×720 30fps 형식은 단일 카메라 캡처를 지원하지만 MultiCam 형식은 아니었다. [사용 중인 WebRTC 구현](https://github.com/webrtc-sdk/webrtc/blob/30d5e63ae91da483e06577b5c35ee91cc5e5c3db/sdk/objc/components/capturer/RTCCameraVideoCapturer.m#L508-L529)은 지원 기기에서 공유 MultiCam 세션을 기본으로 생성한다. 이 조합에서 AVFoundation -11873과 입력 프레임 0개를 확인했다. 앱은 한 번에 한 카메라를 사용하므로 명시적 `AVCaptureSession`을 전달하고 기존 audio session 자동 구성 금지 설정을 유지한다. native 시작 콜백 뒤 실제 session 실행 여부를 확인해 실행되지 않은 카메라를 준비 완료로 처리하지 않는다.

카메라 방향 변경으로 출력 캔버스와 크기가 달라지면 고정 크기 pixel buffer pool을 재사용한다. 대기열은 기존 4프레임 한도를 유지하며 누락 수를 저장 메타데이터와 실기기 검증에 기록한다.

XR에서 세로, 카메라 전환과 가로 방향, relay·peer 재생성 구간을 각각 100초 실행했다. 녹화 시간은 302.7785초이며 원본과 분리 MP4의 영상 8,808프레임, 원본과 분리 M4A의 음성 14,533,368프레임을 전체 디코딩했다. 원본 URL과 바이트를 보존했으며 영상 종료 302.7200초와 음성 종료 302.7785초의 차이는 58.5ms였다. 송출·녹화의 buffer·rotation·timestamp 비교 8,807건에서 불일치 0건을 확인했다. observer 연결 전 최초 1건은 비교 대상에서 제외했다.

XR의 writer 누락 집계는 203프레임이다. 세로 구간 53개, 카메라 전환 구간 2개, relay 재생성 구간 148개였으며 누락 없이 저장했다고 주장하지 않는다. 같은 테스트의 원격 peer는 영상 8,839프레임과 음성 13,968,960프레임을 수신했다. 이는 기기 내부 WebRTC loopback 증거이며 실제 서버 재연결이나 공개 방송의 품질 측정은 아니다.

트랙 종료 시각 비교는 박수·입 모양 등 콘텐츠 기준 동기 검증을 대신하지 않는다. 실제 서버·플랫폼 공개 방송, 네트워크 단절 후 서버 재연결, 사용자 Files destination 선택 및 Photos 저장 완료는 이번 실기기 검증에 포함하지 않았다. 백그라운드 시간 만료·저장 공간 부족·다중 대상 종료는 주입 테스트로 검증했다. 실제 촬영·녹음 파일은 로컬 xcresult에만 보관하며 저장소와 PR에 업로드하지 않는다.

XR의 production recording tap 음소거 검증은 2초 입력·2초 음소거·2초 입력 순서로 실행했다. 중간 구간의 디코딩 음성 peak·RMS는 0이며 전후 실제 마이크 입력과 원격 음성 수신이 유지됐다. sender track은 켠 상태로 recording tap flag만 검증했으므로 실제 UI 음소거 조작의 E2E 결과와 구분한다.

XR UI 렌더링에서 첨부 PNG 59개를 생성했고, 큰 글자 내보내기·저장 목록 대표 화면을 확인했다. 스크롤 화면의 화면 밖 콘텐츠와 native navigation 제목 줄임은 별도 잘림 오류로 집계하지 않았다.
