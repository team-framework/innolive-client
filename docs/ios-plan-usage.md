# iOS 요금제와 방송 가능 시간

대상은 iOS의 요금제 조회·표시와 방송 준비 제한이다. 기존 HTTP 응답을
추가로 읽으며 세션 생성에는 선택한 캡처 해상도에 맞는 `broadcast_resolution`을 보낸다. 서버가 요금제를 이유로 서버 세션의 FHD를 거절하면 720p로 한 번 다시 만든다. WebRTC signaling은 유지한다.
[계약](../contracts/api/plan-usage-v1.md)은 서버의 plan.go와 usage.go를 기준으로 작성했다.

설정과 방송 준비 화면의 ‘요금제 및 사용량’에서 서버·온디바이스를 선택해
각각의 월 한도, 차감 시간, 잔여 시간을 확인한다. 1회 한도는 공통이다.
서버 송출을 지원하지 않는 Spark·Glow는 지원하지 않는다는 안내를 표시한다.
온디바이스 한도·잔여 필드가 없으면 ‘조회 대기’, 명시적인 null이면 무제한으로 표시한다.

서버 방식별 시간과 배수는 `available_by_mode`를 사용한다. 온디바이스는
`device_modes`와 `device_remaining_seconds`를 사용하고, 방식별 배수
1·2·2·3으로 나눈 시간과 1회 한도 중 작은 값을 ‘이번 방송 최대’로 표시한다. 서버 시간 소진이 온디바이스 준비를
막지 않으며 반대도 같다. Glow 온디바이스 FHD 단독 송출을 허용한다.

방송 준비와 방식 변경은 세션의 `ai_processing`을 기준으로 제한한다.
세션이 없을 때는 선택한 AI 방식을 사용한다. 서버 송출 세션에서 로컬
추론만 켜는 기존 경로는 서버 사용량을 적용한다. 조회값이 없으면 서버가
최종 허용 여부를 판단하며, 조회 실패를 소진으로 표시하지 않는다.

방송 중 남은 시간은 서버 세션 조회 또는 직접 송출 heartbeat 응답을
사용한다. 월 80%·100%, 1회 한도 30분·10분 전과 종료 알림을 표시한다.
클라이언트는 월 사용량 0만으로 송출을 종료하지 않는다. 서버가 전달한
`stop_targets`에 따라 직접 송출을 종료하는 기존 동작을 유지한다.

요금제와 사용량 조회가 실패하면 마지막 완전한 조회값과 조회 시각을 유지하고
오류·재시도 버튼을 표시한다. 세션 조회 실패는 마지막 남은 시간과
‘마지막 조회값 · 재시도 중’을 표시하며 다음 조회 성공 때 해제한다.
로그아웃·인증 재설정 때 캐시를 지우고 이전 계정의 늦은 응답을 무시한다.

성공한 요금제·사용량 응답은 계정 ID(액세스 토큰 `sub`)와 조회 시각과 함께
Application Support `PlanSnapshot.json`에 저장한다. 앱 시작 시 같은 계정의 저장값을
네트워크 요청 없이 먼저 표시하고, 로그인 직후 백그라운드 조회로 갱신한다.
서버에 닿지 못한 실패(`transport`)에서 저장값이 있으면 오류 없이 저장값과 조회 시각만 표시한다.
다른 계정의 저장값은 쓰지 않고, 로그아웃·세션 만료 때 파일을 삭제한다.

## 기존 검증 이력

- iPhone 16 / iOS 27 Simulator에서 빌드 성공. 집중 테스트 53개 통과, 실패 0개, 건너뛰기 0개.
- PlanUsageTests: 허용·잠금·무제한·소진, 누락값·잘못된 배수,
  서버 해상도/대상 변경에 따른 방식, 마지막 값 유지·재시도,
  계정 초기화 뒤 늦은 응답, 플랜 불일치 검증.
- PlanAPITests: 두 GET 경로, Bearer 인증, owner token 미전송,
  401 뒤 토큰 갱신과 한 번의 재시도 검증.
- 기존 YouTubeModelsTests와 BroadcastSessionLifecycleTests 회귀 검증.
- LocalizationTests: 한국어·영어·일본어 요금제 문구와 기존 지역화 회귀 검증.
- 영어 항목명과 시간값 배치 수정 후 화면/지역화 테스트 9개 재통과.
- 정상/조회 실패 화면은 테스트 응답으로 렌더링한 이미지로 확인한다.
  프로덕션 요금제 조회, 실제 송출 시간 차감, 물리 기기 검증은 수행하지 않았다.

## BM 보완

- 방송별 사용 내역에 처리 위치 배지, 날짜, 해상도, 플랫폼, 실제 방송·차감 시간 표시
- 방송별 사용 내역은 기본으로 접고 제목에 건수를 표시하며, 누르면 펼친다
- 서버 소진·미지원 시 온디바이스 준비 버튼 제공. 기존 세션 정리 실패 시 새 준비 차단, 계정 초기화 후 늦은 전환 무시
- 전환 후 기존 동의·설정 저장·준비 경로 재사용, 자동 golive 미실행
- 온디바이스 최초 준비의 캡처 preset과 세션 생성 `broadcast_resolution` 일치
- FHD 미지원 시 카메라 720p 선택·송출 대상 축소 안내, 준비 검증 실패 후 해상도 임시 상태 제거로 재시도 허용

## 얼굴 슬롯 화면 확인

- Debug 빌드의 `--face-slot-preview=1` 또는 `=2` 인자는 로그인 없이 Spark(`face_slots=2`) 요금제와 등록 얼굴 1명 또는 2명으로 실제 얼굴 관리 화면을 연다. 이 경로의 `URLSession.shared` 요청은 앱 안 모의 응답으로 끝나고, Release 빌드에는 이 경로가 없다.
- 단위 테스트 호스트에서는 SwiftUI 접근성 트리가 비어 있어 버튼 상태를 읽을 수 없다. `InnoLiveUITests/FaceSlotRegistrationUITests`가 앱을 별도 프로세스로 띄워 1명·이름 입력에서 `얼굴 등록` 활성, 2명에서 제한 문구와 비활성을 확인하고 라이트·다크 화면을 첨부한다.
- 실행 전 `xcrun simctl privacy <device> grant camera com.framework.innolive`로 카메라 권한을 준다.
