# iOS 요금제와 방송 가능 시간

대상은 iOS의 요금제 조회·표시와 방송 준비 제한이다. 기존 HTTP 응답을
추가로 읽으며 요청 형식과 WebRTC signaling은 변경하지 않는다.
[계약](../contracts/api/plan-usage-v1.md)은 서버의 plan.go와 usage.go를 기준으로 작성했다.

설정의 ‘요금제 및 사용량’과 방송 설정·준비 화면에서 플랜 이름, 월 한도,
1회 한도, 월 차감 시간, 월 잔여 시간을 표시한다. 네 방송 방식의 실제
방송 가능 시간과 차감 배수는 서버 응답을 사용한다. 허용되지 않는 행에는
잠금을 표시하고 누르면 플랜 안내를 연다. 허용된 행을 누르면 해당 방식의
시간과 배수를 확인한다. 이 동작은 시간 확인이며 송출 방식 전환 요청을
보내지 않는다. 방송 중 방식 전환과 치지직 연결은 별도 작업 범위다.

서버의 현재 해상도와 활성 송출 대상 수로 현재 방식을 판단한다. 조회된
플랜이 현재 방식을 허용하지 않거나 월 시간이 소진되면 방송 준비를 막는다.
조회값이 없으면 소진으로 간주하지 않으며 서버가 최종 허용 여부를 판단한다.
방송 중 버튼은 경과 시간과 세션의 남은 시간을 구분해 표시한다.
세션 조회는 기존 2초 주기를 유지해 서버의 약 15초 갱신을 반영한다.

요금제와 사용량 조회가 실패하면 마지막 완전한 조회값과 조회 시각을 유지하고
오류·재시도 버튼을 표시한다. 세션 조회 실패는 마지막 남은 시간과
‘마지막 조회값 · 재시도 중’을 표시하며 다음 조회 성공 때 해제한다.
로그아웃·인증 재설정 때 캐시를 지우고 이전 계정의 늦은 응답을 무시한다.

## 검증

- iPhone 16 / iOS 27 Simulator에서 빌드 성공. 집중 테스트 53개 통과, 실패 0개, 건너뛰기 0개.
- PlanUsageTests: 허용·잠금·무제한·소진, 누락값·잘못된 배수,
  서버 해상도/대상 변경에 따른 방식, 마지막 값 유지·재시도,
  계정 초기화 뒤 늦은 응답, 플랜 불일치 검증.
- PlanAPITests: 두 GET 경로, Bearer 인증, owner token 미전송,
  401 뒤 토큰 갱신과 한 번의 재시도 검증.
- 기존 YouTubeModelsTests와 BroadcastSessionLifecycleTests 회귀 검증.
- LocalizationTests: 한국어·영어·일본어 요금제 문구와 기존 지역화 회귀 검증.
- 정상/조회 실패 화면은 테스트 응답으로 렌더링한 이미지로 확인한다.
  프로덕션 요금제 조회, 실제 송출 시간 차감, 물리 기기 검증은 수행하지 않았다.
