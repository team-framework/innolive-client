# iOS 방송 세션 상태

iOS는 세션 생성 직후부터 약 2초마다 `GET /sessions/{id}`를 조회한다. YouTube 단독, CHZZK 단독, 동시 송출 모두 같은 세션 생명주기를 따른다. 세션 종료·초기화 때 조회를 취소하고, 늦은 응답은 세션 식별자·계정 범위·작업 세대가 맞을 때만 반영한다. 계정 전환과 세션 정리의 추가 보호는 후속 작업에서 다룬다.

화면에는 `targets[]` 중 `idle`이 아닌 대상을 표시한다. `targets`가 없는 구형 서버는 기본 `stream`으로 기존 단일 방송 제어를 유지한다. 동시 송출의 라이브 시작은 한 번 요청한다. 일시 중지·재개·종료는 해당 상태인 대상에 개별 요청하며, 한 대상 종료 후 다른 대상의 방송과 세션 조회는 계속된다. `broadcast_remaining_seconds: null`은 무제한과 비방송 상태를 함께 뜻하므로, 방송 중인 경우에만 시간 제한 없음으로 표시한다. 필드가 없으면 잔여 시간을 표시하지 않는다.

방송 준비 경고와 화질 전환 진행·대상별 전환 실패는 상태 영역에 표시한다. `upgrade_offer`의 표시·선택·거절·만료와 추가 플랫폼 설정 흐름은 [iOS 업그레이드 제안](ios-upgrade-offer.md)에 정의한다. 화질 전환과 남은 시간은 서버의 다음 전체 스냅샷에서 갱신한다. `golive` 등 부분 응답은 전체 스냅샷의 시간·알림·미디어 정보를 지우지 않는다.

계약과 예시: [방송 세션 상태](../contracts/api/broadcast-session-state-v1.md). 실제 카메라·WebRTC·방송 플랫폼 동작은 물리 기기에서 별도 확인해야 한다.
