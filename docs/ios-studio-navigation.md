# iOS 방송 화면 탐색

대상은 `apps/ios`다. 2026-10-19의 `origin/main` (`1dd529ca`)에서 방송 화면의 정보와 조작을 3페이지로 분리했다. HTTP·WebRTC signaling 계약은 변경하지 않는다.

## 화면 구성

| 위치 | 역할 | 표시 항목 |
| --- | --- | --- |
| 왼쪽 · 화면 | 영상 확인 | 영상, 방송 중 상태·경과 시간·종료, 필요한 오류 |
| 가운데 · 기본 | 자주 쓰는 조작, 최초 진입 | 영상 조절·얼굴 등록, 방송 요약·준비·시작·제어, 비식별화, 방송 중 채팅·원본 비교 |
| 오른쪽 · 설정 | 방송 세부 설정 | 플랫폼별 상태·정보 편집·제어, 영상·오디오, AI·얼굴, 녹화 목록, 사용량·일반 설정 |

상단 페이지명을 누르거나 좌우로 밀어서 이동한다. 페이지 접근성 값은 현재 페이지명을 읽고, 조절 동작으로 이전·다음 페이지를 선택한다. 접근성 조절은 끝 페이지에서 멈춘다. 전면·후면 카메라 전환은 맨 왼쪽 상단에 두고, 상단 페이지 탭은 화면 중앙에 정렬한다. 계정 버튼은 방송 시작 전 우측에 표시하고 방송 중에는 숨긴다.

준비 전에는 로컬 카메라를 전체 배경으로 보여준다. 준비·연결 이후에는 기존 처리 영상과 연결 상태를 보여준다. 처리 영상 대기 중에 원본을 처리 결과처럼 대체하지 않는다. 일반 영상 대기 안내는 왼쪽 화면 페이지에서 표시하며, 설정 페이지에서는 배경 상태 문구를 숨겨 설정 행 사이에 글자가 겹치지 않게 한다. 기본 페이지의 연결·복구 진행 안내는 유지한다. 기본 페이지의 원본 PiP는 기존 모서리 위치를 기억한다.

영상 레이어는 페이지 컨테이너 밖에 있다. 페이지 선택은 화면 전용 `StudioPage` 값만 바꾸며, 세션·캡처·WebRTC·녹화 작업을 시작하거나 종료하지 않는다. 전체 방송 종료 확인창과 준비 시트는 페이지와 별개의 컨트롤 호스트에 유지한다.

## 조작과 상태

- 카메라 상하 스와이프, 두 손가락 줌, PiP 드래그는 기존 동작을 유지한다.
- 얼굴 선택, 방송 준비·시작·종료, 홈 시트·확인창, 튜토리얼 중에는 페이지 이동을 잠근다. 얼굴 선택 중에는 선택 취소 버튼을 보여준다.
- 상세 페이지는 세로로 스크롤한다. 세부 폼은 시트로 열어 홈과 영상을 유지한다.
- 방송 설정 저장·검증이 성공한 뒤 준비하고, 준비 완료 후 사용자가 방송 시작을 선택한다. 페이지 이동 자체는 준비·시작을 호출하지 않는다.
- 라이브 방송 정보 수정은 대상별 `liveProvider`와 기존 편집 정책을 사용한다. 방식 전환·설정 저장·송출 상태 변경 중 제한을 유지한다.
- 상세 대상 관리에서 플랫폼별 일시정지·재개·종료를 실행한다. 실행 직전에 정책을 재검증하고, 대상 종료는 플랫폼명을 보여준 뒤 확인한다.
- 마이크 오류·대상 시작 실패·화질 전환 실패가 동시에 발생하면 각 안내를 표시한다.
- 저장된 방송 목록은 방송 활성·시작·상태 변경 중 비활성화한다.

## 접근성과 배치

하단은 반투명 단일 바로 구성한다. 준비 전에는 주 동작만, 연결 후에는 방송 조작과 비식별화를 표시한다. 기본 화면의 설정 버튼은 제거하고 설정 탭을 사용한다. 방송 중에는 경과 시간·업로드 FPS·종료 버튼을 높이 32pt의 한 줄 바로 표시한다. 시간과 FPS는 12pt 글씨를 사용한다. 시청자·좋아요·마이크 레벨은 연동 데이터가 없어 표시하지 않는다. 직접 송출의 FPS는 현재 측정값이 없어 대시로 표시한다.

실제 상단 상태 영역과 하단 컨트롤의 높이를 측정해 상세 패널·도구·PiP의 예약 영역에 반영한다. 상세 행의 장식 아이콘은 글씨 확대 시 본문을 침범하지 않게 고정 크기를 사용한다. 투명도 줄이기에서는 상세 패널을 불투명하게 표시한다. 동작 줄이기에서는 페이지명 탭의 전환 애니메이션을 생략한다. 직접 스와이프는 네이티브 paging 동작을 사용한다.

## 검증 경로

- `StudioPageTests`: 페이지 순서·접근성 이동 경계·이동 잠금.
- `StudioHomeRenderingTests`: 대기/라이브 × 3페이지 × 세로/가로/큰 글씨, 실제 native paging scroll 탐색·잠금, 모의 세션 ID와 캡처 정지 상태 유지.
- `StudioDetailsRenderingTests`: 상세 설정·대상 제어의 기본/큰 글씨 렌더링.
- `BroadcastGuideRenderingTests`: 준비 안내와 기본/최소 컨트롤, 긴 제목·빈 제목·큰 글씨, 세션·시작 시각 유지.
- 기존 카메라 제스처·줌·PiP, 방송 준비·수명주기·상태·방식 전환·라이브 편집·튜토리얼·녹화 회귀를 함께 확인한다.

렌더링 테스트는 모의 세션과 비활성 미디어를 사용한다. 검은 배경과 처리 영상 대기 문구는 실제 카메라·실방송 수신을 검증한 결과가 아니다. 실기기에서 연속 좌우 스와이프, 상하 카메라 전환·핀치·PiP 드래그 경쟁, 실제 영상·음성·외부 수신과 녹화 연속성을 추가 확인해야 한다.

2026-10-19 시뮬레이터 검증: 기존 회귀 테스트 139개와 페이지·컨트롤·상세 화면 테스트 10개 통과. 마지막 배치 변경 후 홈·상세 렌더링 테스트 2개를 다시 통과했다. 일반 대기 안내의 페이지별 표시를 수정한 뒤 홈 렌더링 테스트를 한 번 더 통과했다. 홈 18개와 상세·대상 관리 6개의 모의 화면을 생성해 확인했다.

설계 배경: [3페이지 구성 제안](proposals/ios-studio-three-page-ui.md).

## 로컬 화면 확인

Debug 빌드에서 `--studio-preview`로 로그인·미디어 수명주기를 시작하지 않는 UI 미리보기를 연다. `--studio-page-preview`, `--studio-page-details`로 시작 페이지를 선택한다. 페이지 선택 인자는 일반 Debug 실행에도 적용하므로 로그인 상태와 실제 카메라를 유지한 화면을 캡처할 수 있다. Release 빌드는 이 인자를 처리하지 않는다.

2026-10-19 iPhone 16 Pro(iOS 26.6.2)에서 개발 서명 빌드·설치·일반 실행을 확인했다. 기존 로그인 계정과 실제 카메라 미리보기를 유지한 화면·기본·설정 세 페이지를 화면 캡처로 확인했다. 페이지별 재실행 인자를 사용했으며 손가락 스와이프·핀치·PiP 드래그는 이번 실기기 확인에 포함하지 않았다. 확인 후 시작 페이지 인자 없이 일반 기본 화면을 다시 열었다. 방송 준비·송출은 실행하지 않았다.


## 실기기 방송 및 전체 화면 점검

2026-10-19 추가 확인: iPhone 16 Pro에서 YouTube 비공개 방송을 6분 30초 진행하며 세 페이지 스와이프와 설정 시트, 대상 상태, 방송 정보 수정, 카메라·오디오, 영상 조절, AI·얼굴, 사용량·내역, 일반 설정, 방송 제어·비식별화 메뉴, 종료 확인·결과를 캡처했다. 설정값은 변경하지 않았다. 종료 후 원본 저장 안내를 확인했다.

참고 이미지에 맞춘 상단 개편 후 비공개 방송을 약 47초 추가 진행했다. 빨간 경과 시간, 종료 버튼, 실측 30~31 FPS·1080p·배터리와 페이지 변경을 확인했고 방송 종료 결과를 확인했다. 홈·페이지·방송 안내 렌더링 테스트 9개를 통과했다. 마지막 해상도 문자열 표시·접근성 식별자 수정 후 실기기 빌드·설치·실행을 통과했다. 당시 화면 변경 버튼의 순환을 확인했으며, 이후 요청에 따라 중복 버튼을 제거했다.

외부 YouTube 플레이어의 영상·음성 수신은 검증하지 않았다. YouTube 채팅은 로드 오류가 발생했다. 모든 실패 변형, 핀치와 PiP 드래그 경쟁, 전체 설정 조합은 이번 점검 범위에 포함하지 않았다. 화면 캡처는 일반 실행의 실기기 상태이며, 앞선 시뮬레이터 모의 화면과 구분한다.


## UI 후속 수정 · 시뮬레이터 검증

- 상단 카메라·계정 버튼의 수평 패딩을 영상 조절 도구와 같은 24pt로 맞췄다. 페이지 탭 중앙 정렬은 유지한다.
- 준비·시작·종료 전체 화면 안내가 표시되는 동안 배경 영상의 상태 안내와 하단 컨트롤을 숨긴다. 배경에서 연결 진행을 표시하는 동안 주 버튼의 중복 spinner를 숨긴다.
- 설정 탭은 화면에 표시하는 영상 레이어에만 18pt blur와 어두운 덮개를 적용한다. 카메라·WebRTC·녹화·AI 입력에는 필터를 적용하지 않는다.
- 모의 준비 상태를 추가해 대기·방송·준비 × 세 페이지 × 세로·가로·큰 글씨의 27개 화면을 캡처한다. 모의 영상 배경이 검은색이므로 이 캡처만으로 실제 영상의 흐림 강도를 확인할 수 없다.
- E2E 측정과 충돌하지 않도록 이번 수정은 실기기 빌드·설치·실행을 하지 않는다.

시뮬레이터 검증 결과: 준비 흐름 24개와 렌더링 7개, 총 31개 테스트 통과. 마지막 중복 spinner 수정 후 렌더링 7개를 다시 통과했고 27개 홈 캡처를 저장했다. 실기기에는 빌드·설치하지 않았다.


## 작은 상태 바와 가로 배치

사용자 요청에 따라 홈 글씨 크기는 작은 기본 크기로 유지하며 큰 글씨 캡처는 제외한다. 일반 상태 바는 시간·FPS·종료 한 줄로 합쳤으며 복구·일시정지 안내는 해당 상태에서만 추가한다.

가로 화면은 별도 배치로 오른쪽 240pt 영역에 방송 제어를 모으고, 영상 조절·얼굴 등록은 제어 영역 왼쪽에 세로로 쌓아 요약 카드와 겹치지 않게 한다. 설정 페이지는 가용 너비를 사용해 세로 한 열로 구성한다. 세로 화면의 설정은 한 열을 유지한다. 대기·방송·준비 × 세 페이지 × 가로·세로의 18개 모의 화면으로 확인한다. 이번에도 실기기 빌드·설치·실행은 하지 않는다.

후속 조정: 채팅 video ID를 기다리는 안내 문구를 숨긴다. 정보가 도착하면 기존 채팅 표시 경로를 그대로 사용한다. 가로 설정 페이지는 사용자 요청에 따라 세로 한 열로 되돌렸다.

채팅 대기 문구 제거·가로 단일 열 변경 후 홈 렌더링 테스트와 YouTubeViewerChatTests를 통과했다. 세로·가로 모의 화면 18장을 생성해 대기 문구 제거와 단일 열 배치를 확인했다. 실기기 빌드·설치·실행은 하지 않았다.

## Liquid Glass 및 이전 OS

상단 카메라·계정 버튼과 페이지 탭, 작은 라이브 상태 바, 하단 제어 바, 채팅 메뉴·안내에 공통 Glass 표면을 적용한다. 주변 제어를 합치는 상단은 GlassEffectContainer로 묶는다. 설정 내용 카드는 일반 material을 유지해 Glass 표면을 중첩하지 않는다.

iOS 26 이상은 네이티브 Liquid Glass와 glass 버튼을 사용한다. 이전 OS는 regularMaterial·얇은 테두리를 사용하며 영상 위 일반 버튼은 짙은 불투명 채움으로 표시한다. 일반 화면은 bordered 버튼을 유지한다. 투명도 줄이기 또는 대비 증가는 불투명 배경·테두리와 borderedProminent 버튼을 사용한다. 영상 위 표면은 overVideo로 표시해 검정 불투명 배경, 어두운 material 또는 검정 tint Glass를 사용한다. 일반 설정 화면은 시스템 색상 모드를 따른다. 기존 공통 Glass 스타일을 사용하는 설정 화면 등에도 같은 fallback을 적용한다.

이 환경에는 iOS 27 시뮬레이터만 설치되어 있다. fallback 강제 환경값으로 구형 재질 경로와 투명도 줄이기 경로를 렌더링한다. 구형 OS 자체 실행 검증과 구분하며, 실기기 빌드·설치·실행은 하지 않는다.

시뮬레이터 렌더링 테스트 2개를 통과했고, 재질 비교 3장과 홈 상태별 18장을 생성했다. 불투명 경로는 테스트 환경값으로 검증했으며 실제 접근성 설정 변경은 검증하지 않았다. API·미디어 계약 변경은 없다.

## UI 리뷰 수정 검증

- 라이트 모드 영상 위 흰 글씨 대비를 유지하도록 표면과 버튼에 어두운 스타일을 적용했다.
- 가로 도구 열을 240pt 방송 제어 영역 왼쪽으로 이동했다.
- 설정 안의 송출 상태 패널을 평면 채움으로 변경했다.
- 준비·시작·종료 오버레이를 표시할 때 페이지 내용을 숨기며, 준비 덮개 농도를 높였다.
