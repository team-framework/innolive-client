# iOS 방송 세션 정리

iOS는 서버 URL과 로그인 사용자의 JWT `sub`로 구분한 Keychain 기록에
`session_id`와 `owner_token`을 보관한다. 이 구분은 로컬 기록 선택에만 사용하며
서버의 인증과 세션 소유권 검증을 대체하지 않는다.

## 새 세션 생성

- 현재 계정과 서버에 남은 기록이 있으면 먼저 해당 세션을 DELETE한다.
- DELETE `204` 또는 오류 코드가 `not_found`인 `404`만 정리 완료로 인정한다.
- 네트워크·인증·Keychain 오류가 나면 기록을 보존하고 새 세션을 만들지 않는다.
- 생성이 `session_already_exists`로 실패하면 같은 계정과 서버의 기록을 다시
  읽는다. 기록이 있을 때만 그 세션을 DELETE하고 생성을 한 번 더 시도한다.
- 기록이 없거나 DELETE 또는 두 번째 생성이 실패하면 이전 방송을 종료한 뒤
  다시 시도하라는 안내를 표시한다. 다른 계정의 세션을 찾거나 반복 삭제하지 않는다.

## 종료와 계정 변경

명시적 방송 종료와 로그아웃은 세션 DELETE를 시도한다. 로그아웃은 이 시도가
끝난 뒤 인증 토큰을 지운다. DELETE가 실패해도 로그아웃할 수 있으며 정리 기록은
남겨 다음 로그인에서 다시 정리한다. 성공한 DELETE도 읽었던 기록과 현재 기록이
같을 때만 지우므로 나중에 저장된 다른 세션 기록을 지우지 않는다.

비동기 요청은 시작한 계정·서버와 작업 세대를 확인한다. 계정이 바뀐 뒤 도착한
응답은 새 계정의 화면 상태나 인증 정보를 변경하지 않는다. 늦게 도착한 생성
응답의 정리 정보는 원래 계정 범위에 보관한다. 같은 계정의 이전 생성 요청이
끝나기 전에는 새 생성 요청을 시작하지 않아 정리 기록이 덮이지 않게 한다.
같은 사용자의 토큰 갱신은 허용한다.

## 앱 생명주기와 검증

iOS 강제 종료 시 DELETE 실행을 보장할 수 없다. 다음 실행에서 Keychain 기록을
읽어 정리한 뒤 새 세션을 만든다. 백그라운드 전환 자체는 세션을 끝내거나 정리
기록을 지우지 않는다. 기존 YouTube 일시 정지·복귀 동작은 유지한다.

`BroadcastSessionLifecycleTests`는 재실행, 생성 충돌과 한 번의 재시도, 정리 실패,
토큰 갱신, 계정 전환 중 늦은 생성·삭제·로그아웃 응답, 백그라운드 보존을 검증한다.
`BroadcastSessionStoreTests`는 실제 Keychain의 사용자·서버 분리를 검증한다.
강제 종료 후 실제 서버 정리와 실제 YouTube 송출은 기기에서 별도로 확인해야 한다.
