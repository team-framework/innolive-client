# AI 처리 위치와 얼굴 등록

## 세션 생성

기본값은 `server`다. 처리 위치를 고정하는 클라이언트는 기존 서버의 엄격한 JSON 디코더와
호환되도록 `POST /sessions`에 다음 본문을 보낸다.

```json
{"metadata":{"ai_processing":"on_device"}}
```

새 서버는 최상위 `ai_processing`도 받는다. 두 값이 있으면 최상위 값을 우선한다.
허용 값은 `server`, `on_device`이며 그 밖의 값은 400이다. 생성·조회 응답은
선택한 값을 최상위 `ai_processing`으로 반환한다. 세션 생성 뒤에는 변경하지 않는다.
이 고정 모드를 변경하려면 새 세션이 필요하다. iOS의 연결 유지 방식은 아래와 같다.

`on_device` 세션은 서버 AI 스트림을 만들지 않고 처리된 입력 영상을 전달한다.
서버의 `media.anonymization_enabled`는 false다. 이 세션에서 서버 AI를 변경하는
`PATCH /anonymization`은 409 `on_device_processing`을 반환한다.
앱의 비식별화 버튼은 로컬 처리기에 적용한다.

## iOS: 온디바이스 세션과 앱 직접 송출

iOS는 [온디바이스 직접 송출 계약](direct-publish-v1.md)을 따른다. 이 절에는 iOS 구현이 고른
방식과 계약과 다른 점만 적는다.

- 세션 생성: 온디바이스와 앱 직접 송출을 선택하면 `{"ai_processing":"on_device","metadata":{"ai_processing":"on_device"}}`를
  보낸다. 최상위 값은 계약 형식이고, `metadata`는 처리 방식을 돌려주지 않는 구 서버와 협상하는 값이다.
  서버는 최상위 값을 먼저 쓴다. 응답의 `ai_processing`이 `on_device`인지 확인하고, 서버 선택에
  `on_device` 응답이 오면 세션을 지우고 연결하지 않는다. 처리 방식 값을 돌려주지 않는 구 서버에서는
  아래 연결 유지 전환 경로로 서버 AI를 끈다.
- 해상도: `broadcast_resolution`은 보내지 않는다. 서버 기본값은 `720p`이고, iOS는 세션 응답을 받을
  때마다 카메라 화질을 세션 해상도에 맞춘다. 그래서 실제 송출 해상도가 세션 해상도와 같다.
  비트레이트는 실제 프레임의 짧은 변으로 고른다(1080 이상 6Mbps, 그 밖 3.5Mbps).
- WebRTC 유지(계약과 다름): 계약은 이 세션으로 시그널링하지 않는다고 정한다. 서버 main
  (2026-10-12, `981138e`)에는 온디바이스 세션의 협상 타임아웃 예외가 없어, answer가 없는 세션은
  `SESSION_NEGOTIATION_TIMEOUT`(30초, 방송 설정 저장 시 최대 10분) 뒤 삭제된다. 그래서 iOS는 WebRTC
  연결을 유지하고 방송 준비의 영상 입력 확인에도 쓴다. 마이크 트랙은 붙이지 않고 오디오 m-line만
  남긴다. 앱 송출 중에는 이 영상을 300kbps·15fps로 제한한다. 서버에 예외가 들어오면 이 연결을 없앤다.
- 주소: 준비 응답(YouTube)이나 라이브 전환 응답(치지직)에 쓸 수 있는 주소가 없으면 송출을 시작하지
  않는다. 해당 대상의 `stream/stop`을 보내고 오류를 띄운다. RTMP 연결에 실패해도 같다.
  라이브 전환에 실패한 대상(`failed_targets[]`)과 이미 연결한 대상은 연결하지 않는다.
- 종료: `stream/stop` 요청 뒤 연결을 끊는다. 요청이 실패해도 끊는다.
- 음성: RTMP 스트림에는 항상 음성 트랙이 있어야 한다. YouTube는 음성이 없으면 라이브 전환을
  `broadcast_not_ready`로 거절한다. 앱은 마이크를 직접 녹음하고, 끊긴 구간은 무음으로 채운다.
- 재연결: 연결이 끊기면 2초 간격으로 최대 3회 다시 연결한다. 모두 실패하면 해당 대상을 중지한다.
- 상태 표시: 방송 단계는 서버의 `broadcast_phase`를 쓰고, 송출 상태는 로컬 연결 상태로 덮어 표시한다.
- 일시 중지·재개: 서버가 409 `on_device_processing`으로 거부하므로 앱이 처리한다. 연결은 유지하고
  서버 모드와 같은 일시 중지 안내 화면과 무음을 15fps로 보낸다. 백그라운드 전환도 같다. 안내 화면은
  서버 `internal/media/assets/cancel-*.png`와 같은 파일이다.
- 방송 중 송출 방식 전환, 업그레이드 제안 선택, 처리 방식 변경은 막는다.
- 스트림 키: ingest URL은 메모리에만 둔다. 저장하는 세션 기록은 세션 ID와 owner token뿐이다.
  주소 모델의 문자열 표현과 Mirror는 값을 가린다.

## iOS: 직접 송출 하트비트

[계약](direct-publish-v1.md#하트비트)을 따른다. 계약 확정은 server #433에서 다룬다.

- 라이브 전환 응답을 받은 직후 1회, 이후 15초마다 보낸다.
- 409 `heartbeat_not_applicable`, 403 `forbidden`, 404 `not_found`를 받으면 모든 RTMP 연결을 끊는다.
  409는 세션을 다시 조회하고, 403·404는 세션 폴링이 정리한다. 401은 요청 계층이 인증을 갱신해
  다시 보낸다. 그 밖의 오류와 네트워크 오류는 송출을 유지하고 다음 주기에 보낸다.
- `targets[]`는 앱이 송출 중인 대상과 서버에서 라이브인 대상을 합친다. 앱 연결이 없는 라이브 대상은
  `connected: false`로 보낸다. 일시 중지 화면을 보내는 중에도 연결은 `true`다.
- `video.fps`는 직전 보고 이후 인코더에 넘긴 송출 프레임 수 ÷ 경과 시간이다. 첫 보고는 첫 직접
  송출 시작 시각을 기준으로 한다. 일시 중지 화면 프레임은 세지 않는다.
- 누적값(`dropped_frames`, `failed_frames`, `reconnects`)은 세션의 첫 직접 송출부터 센다.
  `dropped_frames`는 인코더 입력 전에 버린 프레임이다(변환 실패, 시각 역전, 인코더 대기열 초과).
- `bitrate_kbps`는 직전 보고 이후 RTMP 송신 대기열에 넘긴 바이트로 계산한다. 첫 보고에서는 생략한다.
- `inference_ms_p50·p95`는 주기 안 가림 처리 추론 시간이다. 비식별화를 끄면 생략한다.
- `device.cpu_pct`는 보내지 않는다. iOS에는 기기 전체 CPU 사용률 공개 API가 없다.
- `stop_targets[]`를 받으면 해당 RTMP 연결을 즉시 끊고 세션을 다시 조회한다.
  `notices[]`와 `broadcast_remaining_seconds`는 세션 응답 값처럼 반영한다.

## iOS: 연결을 유지하는 전환

`server` 세션에서 iOS는 서버 AI를 켜고 끌어 처리 위치를 바꾼다. 온디바이스와 서버 송출을
선택한 경우(client #582)와 구 서버에서 온디바이스를 선택한 경우에도 이 세션을 만들고 카메라 연결 전에
`PATCH /sessions/{id}/anonymization`의 `{"enabled":false}`와 응답 false를 확인한다.
최상위 응답은 서버의 처리 기능을 나타내고, 앱은 실제 선택을 별도로 보관한다.
서버 송출 선택에서는 `ai_processing`과 `broadcast_resolution` 없이 빈 본문을 보내고,
`on_device` 응답이 오면 세션을 지우고 연결하지 않는다. 이 세션은 서버 시간으로 차감된다.

이미 연결한 경우 다음 순서를 따른다.

- 서버 → 온디바이스: 로컬 모델 준비, 로컬 비식별화 경로 활성화, 서버 AI OFF 요청과
  응답 확인. 준비하는 동안에는 기존 서버 경로를 유지한다. 송출 경로가 앱 직접 송출이면
  전환하지 않고 방송 준비 취소를 안내한다. 이 전환은 서버 송출이 되기 때문이다.
- 온디바이스 → 서버: 서버 AI 설정 요청과 응답 확인, 서버로 보낼 프레임 경로 전환.
  응답 전까지 로컬 비식별화를 유지한다.
- 전환 시 세션 ID, owner token, PeerConnection, 카메라 capturer를 유지한다.
  비동기 처리 결과에는 세대를 붙여 이전 경로의 결과가 뒤늦게 전달되지 않게 한다.
- HTTP 실패·누락·불일치 응답은 전환 미확인 상태로 처리한다. 현재 보호 경로를 유지하고
  같은 방식 재선택을 허용한다. 확인 전에는 방송 준비와 비식별화 토글을 막는다.
- 준비 또는 진행 중인 방송에서는 처리 위치를 바꾸지 않는다. 전환 중 방송 준비와
  중복 전환도 막는다.

서버 AI 연결을 열어 두는 비용은 있지만 프레임 추론은 OFF 동안 실행하지 않는다.

## Android: 다음 방송 준비에서 새 세션으로 전환

Android는 설정 화면에 CameraPreview가 없으므로 설정에서 처리 위치를 선택할 때
연결된 미리보기 세션을 닫고 선택을 저장한다. 온디바이스 연결은 첫 보호 프레임이
송출되어야 완료되므로 설정 화면에서 즉시 재연결하지 않는다. 다음 방송 준비에서
카메라를 바인딩한 뒤 새 서버 세션과 PeerConnection을 만들고, 선택한 코덱으로
협상한다. 연결 실패는 방송 준비 오류로 표시하며 방송 준비 API는 호출하지 않는다.
방송 준비·방송·재연결 중에는 처리 위치를 바꿀 수 없다.

Android도 기존 서버와 호환되도록 `server` 세션을 만들고 온디바이스 모드에서는
카메라 연결 전에 서버 비식별화를 OFF로 확인한다. 서버 모드는 서버 비식별화 상태를
확인하며, 온디바이스 모드의 비식별화 버튼은 로컬 처리기를 제어한다.

Android 서버 AI도 방송 설정의 화질(`720p`·`fhd`)을 `POST /sessions`의
`broadcast_resolution`으로 보낸다. 서버는 세션 생성에서만 이 값을 받으므로 화질을
바꾸면 연결된 세션을 닫고 다음 방송 준비에서 새 세션을 만든다. 요금제가 FHD를
허용하지 않으면 생성 요청이 403 `plan_resolution_not_allowed`로 거절된다.

## 저장소

서버 얼굴 등록은 인증 계정에 속하며 기존 `/reference-face` API를 사용한다.
온디바이스 얼굴 등록은 iOS에서 앱 설치의 Application Support에, Android에서
서버 URL과 인증 사용자 ID로 구분한 no-backup 파일에 이름과 임베딩을 저장한다.
Android는 암호화된 파일을 계정별로 분리하며, 계정 소유자를 알 수 없는 기존 공용
파일은 새 계정에 할당하지 않고 제거한다. 사진을 저장하거나 서버로 업로드하지
않는다. 플랫폼 저장소의 보호를 적용하고 백업 대상에서 제외한다. 두 저장소 사이에
자동 복사나 병합은 없다.

서버 등록의 선택적 multipart `name` 및 응답 `faces[].name`은 추가 필드다.
이전 서버는 이름을 저장하지 않을 수 있으므로 서버 이름 보존에는 서버 업데이트가
필요하다. 기존 이름 없는 얼굴은 `등록 얼굴 N`으로 표시한다.
